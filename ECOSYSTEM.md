# Research Ecosystem

This file is a reciprocal map of research that grows around the Reality Bias / Process Reality programme.

It is **not** a citation leaderboard and it is **not** limited to work that cites this repository.

The purpose is to help researchers discover:

- independent replications;
- contradictory or boundary-setting results;
- cross-model or cross-topology validation;
- deeper work on specific Process Reality mechanisms;
- alternative implementations;
- engineering systems;
- benchmarks and evaluation protocols;
- application-domain studies;
- related research that meaningfully overlaps the problem space.

## Inclusion principles

A work may be listed when it is scientifically relevant to the research direction and has enough public information to identify what it contributes.

Possible sources include:

- peer-reviewed journal papers;
- peer-reviewed conference papers;
- substantial preprints;
- public technical reports;
- independently maintained research repositories;
- reproducible engineering implementations.

Inclusion does not imply endorsement, agreement, validation, ownership, collaboration, or authorship by the upstream maintainer.

A paper does not need to cite this repository to be included.

Likewise, merely citing this repository does not guarantee inclusion.

## Adding a work

A pull request or issue may propose an entry with:

- title;
- authors;
- venue or repository;
- year;
- DOI or stable URL when available;
- category;
- one or two sentences describing the relation to this research programme;
- whether it is an independent replication, extension, critique, application, or adjacent work.

The description should state what the work actually contributes rather than merely saying that it cites this repository.

## Reciprocal citation principle

When downstream work makes a meaningful scientific contribution to the evolving research direction, the upstream repository may cite and link back to it.

This reciprocal map is intended to preserve research lineage in both directions:

`upstream framework -> downstream study -> upstream ecosystem map -> later research`.

The success condition is not that every branch remains controlled by one maintainer.

The success condition is that the field becomes easier to trace, test, challenge, and extend.
