# Reality Bias Research Program
## Theory Contract v0.16 — Dynamic CPR as Multi-Dimensional Process Reality Permission Penetration

Date: 2026-09-20
Status: FORWARD / R8 SEMANTIC THEORY UPDATE
Predecessor: `theory/theory_contract_v0.15.md`

## 1. Scope

This contract leaves v0.15 stochastic realization geometry unchanged and upgrades the semantic theory used by forward R8 work.

Reality Bias is modeled as dynamic Process Reality Permission Penetration across three coupled dimensions: information, collaboration/execution boundary, and time.

Process Reality Permission means the degree to which an information item, process scope or historical process is treated as authorized to influence current reasoning, state, invocation, modification or action.

## 2. Shared Process-Reality Layer

A shared pool is not merely storage. It is a reusable process-reality layer through which propositions and their semantic descendants can be read, transformed, cited, operationalized and written back by multiple Agents.

Shared-pool membership does not imply epistemic validity.

## 3. C — Information Permission Penetration

C is not defined as generic hallucination.

C is supported when a proposition lineage with limited independent evidential support acquires stronger reusable or operational reality permission than that evidence warrants.

Dynamic C may occur gradually through:

`source proposition -> role interpretation -> semantic transformation -> descendant reuse -> operational dependency -> stronger reality authority`.

A discrete `unconfirmed -> fact` transition is sufficient only when proposition-level evidence supports the same mechanism; it is not required.

### 3.1 Support separation

R8 must separate:

- `INDEPENDENT_EVIDENTIAL_SUPPORT` — support originating outside the target semantic lineage;
- `LINEAGE_DERIVED_SEMANTIC_SUPPORT` — explanation, transformation, plan, constraint or interpretation descended from the target lineage.

Multiple Agents are not independent evidence merely because they are distinct Agents.

### 3.2 Dynamic C signature

A strong Dynamic C candidate has the form:

`independent evidence stable/insufficient`
`+ semantic descendant support increasing`
`+ operational authority increasing`.

## 4. P — Collaboration / Execution Boundary Permission Penetration

P is not defined as more Agent calls.

P is supported when local completeness, perfection, safety, coherence, review or execution pressures cause the system to enlarge what it treats as authorized process scope beyond the supported boundary.

Dynamic P may include:

- outward expansion to new Agents/tools/information/stages;
- recursive reopening of prior Agents/stages;
- goal enlargement;
- context-surface enlargement that changes existing Agent behavior;
- unrequested repair/addition/refactor/modification;
- silent side execution not represented in the original target.

Process-side and result-side P are both valid candidate forms.

## 5. R — Temporal Permission Penetration

R is a second-order temporal mechanism, not merely a repeated old value.

A retrospective boundary includes audit, review, reopen, rerun, recomputation, recheck, rollback/re-entry or other operations that re-open prior process reality.

R has two semantic forms:

### 5.1 LINEAGE_PRESERVING_R

A prior C/P lineage crosses a valid retrospective boundary and persists, regenerates, launders, normalizes or amplifies without sufficient new independent evidence.

### 5.2 RETROSPECTIVE_GENERATIVE_R

A retrospective operation re-opens the process and itself generates new C and/or P dynamics, even where the newly generated C/P is not identical to the prior deviation.

Healthy independent reconstruction or ordinary correction is not R-positive.

## 6. Coupled CPR dynamics

C, P and R are not assumed independent.

The forward theory permits mutually maintaining transitions:

`C -> P`
`P -> C`
`R -> C`
`R -> P`
`P -> R`
`C -> R`.

No transition is declared merely because the source and target labels coexist. Each edge requires evidence-bound temporal or lineage support.

## 7. Collective Completion

Collective Completion is a candidate mechanism in which multiple Agents produce locally coherent closures over a shared or descended premise, causing lineage-derived support to accumulate without equivalent growth in independent evidence.

Reasonable inference alone is not sufficient.

A critical audit question is whether apparent multi-Agent corroboration is genuinely independent or is descendant self-support from one root lineage.

## 8. Permission penetration versus propagation

Propagation means information/process state travels.

Permission penetration means the traveled object obtains additional operational force or authorized reach.

`visible -> read -> referenced -> interpreted -> adopted -> operationally effective`

Not every propagated object penetrates a permission boundary.

## 9. Relationship to System Inertia

System Inertia is structural/mechanistic persistence after direct stimulus or challenge is absent.

System Inertia may be healthy.

CPR requires a separate semantic finding that the relevant information/scope/time permission exceeded its justified boundary.

Thus:

`System Inertia != R`

but System Inertia may carry a C/P lineage into an R window.

## 10. R5 as observational cut

R5 does not define CPR.

Its one-shot challenge provides a useful cut through an already-realized process, exposing response families such as:

- carry-through;
- independent re-anchoring;
- recomputation;
- descendant-lineage continuation;
- new semantic compensation.

R8 may use these frozen responses to identify the first observable semantic compensation point without claiming an absolute historical origin.

## 11. Evidence discipline

Every R8 claim must bind to frozen evidence refs.

Reviewers may not invent missing lineage, hidden reasoning, unrecorded authority or unrecorded scope.

Allowed outcomes include `NON_CPR`, `UNRESOLVED`, `NOT_APPLICABLE` and disagreement.

## 12. Dynamic claim units

R8 may report:

- semantic events;
- permission-boundary transitions;
- semantic-support accumulation;
- independent-evidence additions;
- shared-pool re-entry;
- recursive reopening;
- C/P/R transition edges;
- coupled episodes;
- recovery or non-CPR episodes.

Task-level one-label classification is not required.

## 13. Nonclaims

This theory does not claim that:

- every uncertain item becomes C;
- every multi-Agent explanation is pseudo-corroboration;
- every additional Agent is P;
- every audit/recompute is R;
- every R event preserves the old lineage;
- every C causes P;
- every P causes C;
- CPR must form a closed loop;
- the absolute origin of a distributed CPR episode is always identifiable.
