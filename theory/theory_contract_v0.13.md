# Reality Bias Research Program
## Theory Contract v0.13 — Lineage Packages, Repair Lifecycle and Deferred CPR Semantics

Date: 2026-09-18  
Status: FORWARD / PROCESS REALITY v5.2  
Predecessor: `theory/theory_contract_v0.12.md`

## 1. Scientific object

Process Reality studies whether source epistemic state, semantic boundary and decision meaning remain faithful as information moves through a multi-Agent process and becomes reusable system reality.

## 2. Dynamic formation

The forward formation chain remains:

`Multi-source conditions -> Unstable Information -> Escape Structure -> Semantic Transformation -> Structural Support -> Stable Shared Information Pool -> Semantic Descendants`

The exact realized path may differ by run.

## 3. Repair Anchor and repair unit

A Repair Anchor is a machine-addressable entry point selected for control efficiency.

It is not the full repair object and is not assumed to be semantic origin, first support or first pool entry.

The engineering repair unit is the relevant Semantic Lineage Package: the target semantic object together with evidence-supported transformations, authority states, pool representations, adoptions, dependent decisions and descendants.

## 4. Lineage-bounded locality

Localized repair is defined by lineage scope, not by event count or temporal shallowness.

A local repair may span many Agents and events when they belong to the same relevant lineage.

Unrelated semantics should remain outside the repair package unless evidence establishes dependency.

## 5. Hash lineage and content addressing

Content addressing answers which semantic object/revision is being operated on.

Hash lineage answers how that object changed, propagated, was adopted and produced descendants.

Content identity alone does not prove semantic adoption. Relation evidence remains necessary for semantic-use claims.

## 6. Repair lifecycle

The engineering lifecycle is:

`Observe -> Scout -> Address -> Build Lineage Package -> Gate -> Repair -> Selective Recompute -> Bind New Lineage -> Reinforced Watch -> Stabilize/Reopen`

Repair does not end at state mutation. Post-repair monitoring is part of the engineering lifecycle because later re-entry or new descendants may emerge after the direct repair.

## 7. Three-arm observation parity

C1, C2 and C3 must expose the same observation surface over descendants and lineage evolution.

Different intervention depth must not be confounded with different observation depth.

## 8. R7/R8 separation

R7 records structural facts and executes authorized engineering operations.

R8 interprets frozen evidence semantically.

R7 must not pre-label machine observations as C, P, R, collective completion, authority migration or semantic recurrence.

## 9. CPR event semantics

CPR interpretation may be event-level, repeated, overlapping and transition-based rather than a single exclusive task label.

This contract permits R8 to test such interpretations but does not pre-establish them as universal laws.

## 10. Authorization

This theory contract authorizes no provider call, evaluator call, active repair or CPR adjudication.
