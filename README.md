# reality-bias-benchmark

Open research repository for the **Reality Bias** programme and the first-paper **Process Reality** mechanism study in multi-agent AI systems.

> **Open for use. Clear in provenance. Responsible in evolution.**

This repository is designed for replication, independent validation, criticism, extension, alternative implementation, and downstream research.

## What is Process Reality?

Multi-agent AI systems can preserve a plausible or even unchanged final answer while changing what they treat as sufficiently authorized during execution.

This repository studies that process-level layer:

- what information may be treated as real or established;
- what supporting work may become operationally required;
- what historical process state may re-enter and influence current execution;
- how those changes propagate through messages, shared state, calls, semantic descendants, and repair.

The first natural anchor was simple.

A Product A inventory reading of about **1,520 units** entered an e-commerce planning process as **preliminary and unreconciled**. Several agents transformed and reused it. Later, the same value was rewritten as a factual/reconciled object and consumed by the final plan, even though no new warehouse reconciliation had entered the frozen trajectory.

The number did not change.

**Its permission to count as reality did.**

A matched natural trajectory preserved the uncertainty and used the same value conditionally. That contrast is why ordinary information propagation is not enough to define the phenomenon.

## Core research object

The study treats **Process Reality** as the evolving set of information, process obligations, and historical states that an interacting AI system treats as sufficiently authorized to influence current execution.

The current semantic organization uses three dynamic dimensions:

- **C — information permission penetration**: information or semantic descendants gain greater epistemic or operational authority than their independent evidence supports;
- **P — collaboration / execution-boundary permission penetration**: supporting work, checks, calls, or generated requirements acquire operational force beyond the supported task boundary;
- **R — temporal permission penetration**: earlier process reality re-enters, strengthens, or generates later C/P effects through review, reopening, recomputation, backflow, or related retrospective paths.

C/P/R are not three mutually exclusive static labels. They can overlap and interact through shared process state.

## Study structure — not R-series chronology

> **Important:** the historical R labels are research-development coordinates, not a strict sequential experimental pipeline.

The study was operated by **structure and evidence role**, not by mechanically executing R2, then R3, then R4, and so on.

A single frozen natural trajectory can support several analytical views at once. Some later R labels describe retrospective semantic reconstruction or engineering interpretation rather than a new subject run.

The scientific structure is better represented as:

```text
natural multi-agent task
  -> complete trajectory recording
  -> raw evidence freeze
  -> trajectory-first semantic reconstruction
       |-> information-authority change
       |-> process-scope change
       |-> temporal re-entry
  -> localized mechanism probe
  -> lineage / inertia identification
  -> bounded lineage-addressed repair
  -> complete post-intervention semantic comparison
```

The probability and mechanism layers are also deliberately separated:

```text
Probability layer
Domain environment
  -> natural stochastic trajectory population
  -> occurrence / distribution

Mechanism layer
Realized natural case
  -> semantic reconstruction
  -> optional one-point challenge
  -> lineage / inertia identification
  -> optional repair
```

Repeated continuations from one frozen parent do **not** become a new domain-prevalence estimate.

## Main observations

### 1. Natural authority migration

An uncertain source can remain numerically unchanged while its semantic descendants gain greater authority.

The e-commerce discovery case shows:

```text
~1,520 preliminary / unreconciled
  -> downstream calculation and reuse
  -> no new warehouse reconciliation
  -> ~1,520 fact / reconciled
  -> final-plan consumption
```

A healthy comparator preserved conditional semantics instead of upgrading the source authority.

### 2. Goal-preserving process expansion

The requested endpoint can remain stable while the process surface grows.

In held-out Software Engineering trajectories, generated validation and ownership requirements could become operational obligations, enter shared state, trigger new calls, and constrain advancement while the user-facing requested output remained the same kind of release decision.

Invocation count alone is not Dynamic P. The audit compares:

```text
original goal
vs
supported authorization boundary
vs
realized process scope
vs
final result / actual change
```

### 3. Functional Semantic Lineage

Literal wording is not the only thing that propagates.

A source proposition may disappear while its operational meaning survives through transformed descendants.

The repository therefore distinguishes:

- propositional continuity;
- semantic transformation;
- functional semantic continuity;
- independent re-anchoring;
- source-specific persistence.

This allows a later object to be traced by what role it plays, not only by whether it repeats the original words.

### 4. A weak local challenge can reveal dependence

Canonical R5 uses a deliberately weak intervention.

For a selected already-realized source object, the next relevant reader sees one reduced-authority view, typically:

`fact -> unconfirmed`

The persistent historical source state is not rewritten, and the intervention is not repeatedly reinjected.

The 29 canonical R5 cases were heterogeneous:

- some ignored the challenge;
- some recalculated;
- some explicitly reasoned about the uncertainty;
- some used independently supported descendants;
- some preserved source-specific downstream structure.

R5 is therefore interpreted as a **localized response/dependence probe**, not an average treatment-effect estimator.

### 5. Persistence is not automatically System Inertia

R6 introduces no new subject-model run.

It reconstructs:

```text
source
  -> local response
  -> semantic carrier
  -> downstream read / use
  -> decision-action dependence
  -> post-stimulus persistence
  -> affected continuation
```

A continuation that independently rebuilds support can be healthy even if the endpoint is unchanged.

A stronger System Inertia candidate requires evidence that a source-related semantic structure continues to constrain later process after the direct stimulus disappears.

### 6. The same endpoint can have different evidential ancestry

R7 compares bounded intervention modes over lineage-complete cases.

Across four paired repair cases:

- two materially diverged;
- two reconverged to the same broad endpoint through a different internal evidential route.

This is why final-answer equality is not sufficient to establish process equality.

## Reproducibility principles

### Freeze once, review many times

Subject trajectories are recorded and frozen before later semantic questions are asked.

A new reviewer, semantic rubric, or analysis question does not by itself justify rerunning the subject.

### Structure locates; semantics adjudicates

Structural scouting is used to reduce search cost and expose candidate paths.

It is not treated as the final semantic verdict layer.

### Exact output divergence is not automatically causal evidence

Multi-agent subject models are stochastic.

A changed branch is interpreted through semantic lineage, independent evidence, process role, and the realized path rather than by output inequality alone.

### Censoring stays visible

A trajectory terminated with pending work, unread messages, queued calls, or active continuation is not converted into a clean negative tail.

Positive prefix evidence may remain usable, but unobserved continuation is not invented.

### Historical evidence remains inspectable

Superseded analyses and earlier interpretations are preserved where needed for auditability.

Later theory does not silently rewrite earlier raw evidence.

## Current boundaries

The repository supports inspection of the reported mechanism and engineering evidence, but it does not claim that the first study establishes:

- universal C/P/R prevalence;
- cross-model robustness;
- cross-provider robustness;
- cross-topology robustness;
- independent external replication of the final semantic labels;
- universal superiority of one repair surface;
- a universal multi-agent failure taxonomy;
- experimentally established Human–AI or arbitrary system-to-system Process Reality.

Those remain replication, extension, or future research directions.

## Short version

**The endpoint is not the whole process.**

This repository studies how information, obligations, and historical states gain or lose authority inside multi-agent AI systems, how those changes can be traced through Functional Semantic Lineage, and how affected lineages can be challenged or repaired without discarding the entire run.
