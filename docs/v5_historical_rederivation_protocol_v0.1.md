# Process Reality v5 Historical Re-derivation Protocol v0.1

Date: 2026-09-18  
Status: FORWARD OFFLINE RE-DERIVATION / FROZEN EVIDENCE ONLY / NO NEW SUBJECT EXECUTION

## 1. Purpose

This protocol re-projects existing frozen R2-R6 evidence into Process Reality v5 objects without rewriting historical evidence, condition IDs, design hashes or prior reports.

The objective is not to prove that the v5 theory is correct by definition. It is to test whether existing evidence can support a bounded chain such as:

\`unstable source -> semantic transformation -> structural support -> stable shared pool -> exposure anchor -> downstream constraint\`

Any unsupported link must remain \`NOT_ESTABLISHED\`.

## 2. Allowed evidence

Re-derivation may consume only:

- frozen raw subject evidence;
- frozen structural derivations;
- append-only semantic audit records;
- existing report evidence tables that preserve exact trace/event/state refs;
- immutable run/artifact/hash bindings.

No missing event may be reconstructed as fact.

## 3. Legacy J0 treatment

J0 is treated as a frozen selected anchor ID.

The re-derivation must separately ask:

1. Is J0 the earliest semantic origin?  
2. Is J0 the first Structural Support point?  
3. Is J0 the first Stable Shared Pool entry?  
4. Is J0 a later Structural Exposure anchor?  
5. Is the evidence insufficient to decide any of the above?

No answer is assumed in advance.

## 4. Required object ladder

For each candidate chain, report independently:

- \`UNSTABLE_INFORMATION_CANDIDATE\`
- \`SEMANTIC_TRANSFORMATION_CANDIDATE\`
- \`STRUCTURAL_SUPPORT_CANDIDATE\`
- \`STABLE_POOL_ENTRY_CANDIDATE\`
- \`DIRECT_POOL_CONSUMPTION_CANDIDATE\`
- \`STRUCTURAL_EXPOSURE_CANDIDATE\`
- \`DOWNSTREAM_CONSTRAINT_OR_ACTION\`

Each object must carry:

- evidence refs;
- claim status;
- alternative interpretation where material;
- whether the object is mechanically derived or semantically audited.

## 5. Ordering rule

Event order may show that one observed candidate precedes another, but:

\`earlier observed event != causal origin\`

and:

\`later exposure != first support\`

The protocol must not silently infer missing intermediate links.

## 6. R5/R6 reinterpretation

Historical R5 one-shot results are re-read as driver-probe evidence:

- did the local source-status annotation propagate?
- did source value/state remain addressable?
- did descendants/pool states remain available?
- did downstream constraints remain semantically usable?

Historical R6 results are re-read as support/trace evidence:

- where was persistent addressable state located?
- which downstream descendants remained visible/adopted?
- which candidate surfaces could plausibly carry persistence?
- what remains unresolved about source versus structure drive?

## 7. Batch identity

R2-R4 Batch001 and the later J0-bearing R5/R6 parent remain separate evidence sets.

Cross-stage synthesis is an audit projection, not a fabricated continuous subject trajectory.

## 8. Output status

Allowed mapping statuses:

- \`DIRECTLY_EVIDENCED\`
- \`SUPPORTED\`
- \`SUPPORTED_CANDIDATE\`
- \`UNRESOLVED\`
- \`NOT_ESTABLISHED\`
- \`CONTRADICTED\`
- \`NOT_ADJUDICATED\`

## 9. Authorization

This protocol authorizes no provider run, evaluator run, CPR adjudication, repair or subject rerun.
