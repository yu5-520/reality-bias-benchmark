# Process Reality v5 Whole-Process Experiment Protocol v0.1

Date: 2026-09-18  
Status: FORWARD CORE EXPERIMENT PROFILE / NOT YET AUTHORIZED FOR SCIENTIFIC PROVIDER EXECUTION

## 1. Objective

Future Process Reality experiments should collect a complete process lifecycle once and reuse the frozen evidence for multiple later analyses.

The expensive object is the real multi-Agent trajectory, not the semantic review.

Default chain:

\`\`\`text
prepare
  -> natural multi-Agent run
  -> freeze raw evidence
  -> integrity validation
  -> structural indexing
  -> support / pool / exposure scouting
  -> localized semantic audit
  -> optional minimal driver probe
  -> upstream + downstream trace
  -> optional intervention-surface experiment
  -> recovery observation
  -> export reusable review bundle
\`\`\`

## 2. One run, multiple analysis views

One frozen run may later support:

- R2-R4 natural formation analysis;
- unstable-information audit;
- semantic-transformation audit;
- Structural Support localization;
- Stable Shared Pool analysis;
- Structural Exposure scouting;
- R5 driver analysis;
- R6 support/trace/control-surface analysis;
- R7 repair/recovery analysis if separately authorized;
- R8 CPR adjudication;
- R9 supplementary reviewers.

These views do not require separate subject reruns unless the scientific design specifically requires a manipulated branch.

## 3. Core subject phase

The default subject phase is natural and minimally instrumented.

The runtime should record, where available:

- every actual model input/output;
- message send/delivery/read;
- state read/write/revision;
- evidence source refs;
- invocation/tool execution;
- queue and termination state;
- actor and turn;
- hashes/version identities;
- authority/evidence metadata already present in runtime;
- resource use.

No all-event semantic Judge Agent is required in the subject loop.

## 4. Freeze before interpretation

Mandatory order:

\`subject -> raw freeze -> integrity validation -> structural derivation -> semantic audit\`

A semantic disagreement must not trigger an outcome-aware subject rerun.

## 5. Structural scout phase

The scout operates over frozen/streamed structural evidence and emits bounded candidate regions.

The scout should not decide CPR or semantic truth.

Primary engineering readout:

\`audit_surface_reduction = all_candidate_events / all_recorded_events\`

where the exact denominator/numerator must be frozen before any confirmatory claim.

## 6. Localized semantic audit phase

Semantic audit examines only the selected candidate region plus the minimum upstream/downstream closure needed to interpret it.

The audit may expand the local window when evidence shows a source-backed relation crossing the initial boundary. Any expansion must be logged.

## 7. Driver probe phase

A driver probe is optional and hypothesis-specific.

The existing \`fact -> unconfirmed\` operation is one allowed historical family.

Future probe families may include, only under separately frozen design:

- source epistemic withdrawal;
- dependency invalidation;
- descendant withdrawal;
- pool-entry revision;
- action-constraint revision.

One probe should not be interpreted as a universal test of all support mechanisms.

## 8. Control-surface phase

When a manipulation is scientifically justified, candidate surfaces may include:

- source;
- early semantic-transformation node;
- Structural Support point;
- Stable Shared Pool entry;
- derived constraint/action node;
- evidence-supported RepairClosure.

The experiment must name detection surface, trace root and intervention surface separately.

## 9. Recovery phase

R7 is optional. It requires explicit authorization and a frozen recovery operator.

Recovery data remain separate from natural formation evidence.

## 10. Reusable dataset principle

Each batch should export a reusable, content-addressed evidence bundle so later questions can be evaluated without rerunning the subject.

The bundle should support new append-only audits while preserving original raw evidence identity.

## 11. Optional robustness

Target-specific comparisons, matched factual controls, extra reviewers/models and additional domains are activated only when required by the hypothesis.

They are not default prerequisites for every Whole-Process Run.

## 12. Authorization

This protocol alone authorizes no provider/evaluator execution or active repair.
