# R7 Localized Structural Recovery Protocol v1.0

Date: 2026-09-18  
Status: FORWARD v5 / ACTIVE PHASE REQUIRES SEPARATE AUTHORIZATION

## 1. Purpose

R7 tests whether an evidence-supported process-reality problem can be repaired at an explicitly selected intervention surface while preserving unrelated process freedom.

## 2. Entry objects

R7 should receive:

- detection surface;
- trace root;
- selected intervention surface;
- evidence-supported affected closure;
- mechanically required replay dependencies;
- repair closure;
- preserved refs;
- revision identity strategy.

## 3. Valid repair surfaces

A repair may target:

- source;
- Structural Support;
- Stable Shared Pool entry;
- derived constraint/action;
- bounded RepairClosure.

The repair surface does not have to equal the detection surface.

## 4. Locality

A localized success requires both:

1. the targeted process-integrity condition improves under the frozen recovery criterion;
2. unrelated/preserved structure remains unchanged within the declared measurement boundary.

Whole-system suppression does not count as localized success.

## 5. Recovery verification

Record:

- revised state/revision identities;
- downstream direct consumers;
- residual old lineage;
- old-lineage re-entry;
- repaired descendant recomputation;
- preserved branches/fields;
- terminal outcome separately.

## 6. Release

Active repair ends under a preregistered release rule, after which free routing resumes.

Later recurrence is evidence, not automatic protocol failure.

## 7. Semantic boundary

R7 does not decide CPR merely because a repair succeeded.

## 8. Authorization

Any active scientific repair requires a separate explicit gate.
