## 1. Paper architecture

The first paper is organized into three argument layers.

### Part I — Theory / Phenomenon

Question:

> How does Process Reality form and persist in a multi-Agent system?

Primary objects:

`Unstable Information -> Escape Structure -> Semantic Transformation -> Structural Support -> Stable Shared Pool -> Semantic Descendants`

Evidence form:

`Frozen Process Evidence -> Semantic/Relation Audit -> Bounded Mechanism Interpretation`

This section does not need to identify a universally fixed formation path.

### Part II — Engineering / Control

Question:

> Once problematic shared reality is structurally exposed, can the system address the complete relevant semantic lineage and repair it without scanning or damaging unrelated semantics?

Primary objects:

`Structural Repair Anchor -> Content Address -> Semantic Lineage Closure -> Completeness Gate -> Repair Closure -> Recovery`

The engineering objective is not to find every semantic path in the task.

It is to recover the complete relevant history of the target semantic object while excluding unrelated semantic branches.

### Part III — Discussion / Future

Question:

> What would a portable Process Integrity layer look like across Agent runtimes and domains?

This section may discuss:

- pluggable Process Integrity Protocols;
- cross-framework adapters;
- cross-domain replication;
- semantic/epistemic integrity infrastructure;
- real-time scouting and authorized repair.

Future discussion must remain separated from demonstrated experimental results.

## 2. Local repair definition

Localized repair means:

`LOCAL_BY_SEMANTIC_SCOPE`

not:

`LOCAL_BY_TRACE_DEPTH`.

A repair scope may span the entire run if the target semantic lineage spans the entire run.

Unrelated semantics remain outside the repair packet.

## 3. Structural Repair Anchor

The paper may reinterpret a historical Jump/J0-like node as a candidate Structural Repair Anchor when it is:

- sufficiently exposed;
- content-addressable;
- provenance-bound;
- linked to downstream descendants;
- cheaper to scout than all-event semantic review.

Repair-anchor value comes from operational clarity and repair efficiency, not from being the earliest semantic origin.

## 4. Content-addressed semantic lineage

From a Repair Anchor, the system should be able to retrieve:

- upstream source;
- epistemic/authority history;
- semantic transformations;
- adoption relations;
- pool states;
- relevant revisions;
- downstream constraints/actions;
- evidence pointers.

This set is the Semantic Lineage Closure.

## 5. Completeness before repair

A Repair Agent should receive a complete relevant semantic history, not merely a nearby time window.

When critical lineage is missing:

`LINEAGE_GAP`

must be preferred over semantic reconstruction as fact.

This is a core engineering safety principle because an under-informed Repair Agent can create a new Reality Bias while attempting to repair the first one.

## 6. Theory experiment success criteria

Theory experiments evaluate:

- existence of unstable information;
- semantic transformation;
- cross-Agent adoption;
- stable shared-pool existence;
- semantic descendant persistence;
- source/pool status decoupling;
- bounded alternative explanations.

They do not require successful repair.

## 7. Engineering experiment success criteria

Engineering experiments evaluate:

- Repair Anchor detectability;
- content-address precision;
- relevant-lineage recall/completeness;
- unrelated-context reduction;
- Lineage Completeness Gate behavior;
- RepairClosure size;
- repair/recompute correctness;
- preservation of unrelated structure;
- old-lineage re-entry;
- detection/audit/repair cost.

They do not require localization of the globally earliest semantic origin.

## 8. Historical compatibility

Historical theory/experiment reports remain frozen.

The theory report and engineering report are separate artifacts. Future discussion does not retroactively change either evidence layer.
