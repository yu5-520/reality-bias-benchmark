## 1. Purpose

R7 asks whether inherited system inertia can have its **direction, persistence, localization or recoverability changed by structural handling**.

This protocol makes two corrections to the earlier forward framing:

1. R7 is broader than ALR. R7 is the system-level controllability/steering question.
2. ALR is one specific Authority-Localized Recovery operator used as a treatment arm, not a synonym for all structural control.

The protocol does not assume successful control. It measures observed steering, localization, preservation, recovery, recurrence and failure modes.

## 2. Relationship to R5 and R6

```text
R5: one-shot perturbation
  -> can a local change reorganize the path?

R6: post-reorganization inertia
  -> what inherited tendency persists, transforms, returns or reconverges?

R7: structural handling
  -> can the direction or recoverability of that inertia be changed without prescribing terminal content?
```

R7 therefore begins only after a valid J0 and source-backed downstream structure exist.

## 3. Core R7 question

> Given the same natural Jump boundary and materially equivalent correction information, how do one-shot free continuation, continuous field exposure and authority-localized structural recovery differ in the downstream process structure they produce?

A stronger proposition may be tested but not assumed:

> Inherited process inertia has locatable structural carriers and can therefore be subjected to local, lineage-aware, verifiable recovery.

## 4. Common frozen parent / J0

Where runtime support permits, all R7 arms must start from the same frozen parent state and the same selected J0 boundary.

Common invariants should include:

- task goal;
- role/responsibility pool;
- model/provider binding;
- base prompts;
- semantic correction payload;
- passive observability schema;
- continuation budget/horizon or explicit censoring rule;
- structural detector/measurement versions.

If exact equivalence is not possible, the difference must be reported rather than hidden.

## 5. C1 — One-Shot Free Continuation

C1 reuses the R5 causal envelope.

```text
Frozen J0
  -> one direct experiment-origin exposure
  -> consume intervention
  -> no persistent experiment-origin mutation
  -> no reinjection
  -> free downstream evolution
```

C1 answers:

> What inertia remains when the experiment-origin signal leaves active context after one bounded exposure?

Evidence label:

`ENDOGENOUS_INHERITED_INERTIA`.

C1 is not required to produce recovery.

## 6. C2 — Persistent Field Propagation

C2 supplies the same semantic correction field/signal continuously to downstream nodes.

```text
Frozen J0
  -> correction field visible
  -> later node: same field remains visible
  -> later node: same field remains visible
  -> ...
```

C2 answers:

> What process structure appears when the experiment continuously maintains the correction signal?

Evidence label:

`EXPERIMENT_MAINTAINED_FIELD_PERSISTENCE`.

C2 persistence must not be described as endogenous system inertia because the experimental signal remains active.

## 7. C3 — ALR Authority-Localized Recovery

C3 uses the same correction semantics but changes the structural handling.

```text
Frozen J0 / named authority-provenance breach
  -> locate earliest violating ancestor n*
  -> compute affected dependency closure
  -> preserve unaffected realized structure
  -> repair breached authority/provenance condition
  -> create revision identity/hash
  -> reopen/re-execute affected subgraph only
  -> free/generative continuation within the repaired structural state
  -> observe residual / recurrence / transfer / re-entry / reconstruction
```

Evidence label:

`ALR_LOCALIZED_STRUCTURAL_RECOVERY`.

C3 answers:

> Does localized structural recovery produce a different downstream process than merely carrying the same correction field continuously?

## 8. R7-A — endogenous inertia versus maintained persistence

Primary contrast:

`C1 vs C2`.

Core interpretation:

- C1 retains only downstream consequences that survive after the experiment-origin signal exits active context;
- C2 retains an experiment-maintained signal by design.

Measure whether continuous exposure changes:

- descendant Jump frequency/distance;
- root reach/depth;
- actor transition sequence;
- cross-Agent spread;
- branch/merge/re-entry;
- path-family distribution;
- state-lineage destination;
- reconvergence distance.

This contrast protects the study from confusing **system inertia** with **continuous experimental forcing**.

## 9. R7-B — persistent content versus localized structural recovery

Primary contrast:

`C2 vs C3`.

The semantic correction payload should be matched as closely as possible.

The treatment difference is:

- C2: keep the semantic signal continuously available;
- C3: use source-backed authority/dependency structure to localize, revise and reopen only the affected subgraph.

Measure:

- affected-descendant localization precision;
- affected vs preserved set size;
- preserved node/field/branch ratio;
- reopened node count;
- old-lineage survival;
- residual/recurrent lineage;
- post-recovery re-entry;
- secondary Jump formation;
- path reconstruction;
- structural direction shift;
- reconvergence/recovery distance.

## 10. Semantic payload matching

C2 and C3 must not differ merely because ALR receives a better correction message.

The run contract should freeze:

- correction field key;
- before/after semantic state;
- textual/structured payload hash where applicable;
- source evidence available to the correction;
- delivery timing relative to J0.

C3 may carry additional **structural metadata** required for dependency closure and revision identity, but it must not receive extra task-solving content that C2 lacks.

## 11. No target answer

No R7 arm may be instructed to produce a desired terminal answer merely to create apparent recovery.

The intervention may change:

- authority/provenance condition;
- structural routing/reopen scope;
- field revision identity;
- visibility/propagation mode.

The downstream subject process remains generative.

## 12. Structural direction

R7 uses direction as an observed graph/transition property.

A run contract may operationalize direction through:

- actor transition sequence;
- edge distribution;
- state-lineage destination;
- information-flow destination;
- descendant-Jump location;
- re-entry topology;
- stage progression;
- path-family transition;
- reconvergence location/distance.

A literal mathematical vector is optional and not required for the first proof.

## 13. Common evidence capture

All three conditions must use materially equivalent passive structural observation.

At minimum capture:

- raw prompts/outputs and parsed actions where permitted;
- message send/delivery/read;
- invocation proposal/execution;
- state read/write/revision;
- actor/role/turn;
- parent/start-state identity;
- final/reopen/revision operations;
- queue/pending/error/censoring state.

A claim that ALR is more traceable is invalid if only the ALR arm records the lineage required to establish traceability.

## 14. ALR-specific evidence object

C3 additionally records treatment-specific structure:

- authority/provenance condition id;
- earliest violating ancestor `n*`;
- source evidence refs;
- dependency-closure algorithm/version;
- closure hash;
- affected set;
- preserved set;
- prior revision/hash;
- repaired revision/hash;
- parent revision;
- reopened/re-executed subgraph;
- preserved untouched structure;
- resulting new descendants.

This is treatment metadata, not a richer natural-observation substrate.

## 15. Proposal versus realization

If ALR blocks, redirects or reopens an action, retain both:

- the subject's original proposal;
- the realized action/state after structural handling.

Do not erase attempted behavior from the evidence record.

## 16. Primary outcomes

### Process-structural outcomes

- Jump / descendant Jump lineage;
- root reach/depth;
- branch/merge/re-entry;
- cross-Agent relation;
- path-family shift/reconstruction;
- state inheritance;
- residual old inertia;
- recurrence/rebound;
- secondary Jump formation;
- structural steering direction;
- reconvergence/recovery distance;
- affected/preserved topology.

### Preservation outcomes

- unaffected nodes preserved;
- unaffected fields preserved;
- unaffected branches preserved;
- unnecessary reopen count;
- full rerun avoided/invoked;
- non-risk Agent participation retained;
- non-risk path diversity retained.

### Secondary outcomes

- terminal task result;
- turns/model calls;
- token/spend;
- latency;
- execution cost.

Terminal correctness cannot define R7 success by itself.

## 17. Possible scientific outcomes

R7 may observe:

- attenuation;
- redirection;
- delay;
- localization;
- successful local recovery;
- partial recovery;
- transfer to another lineage;
- recurrence/rebound;
- path reconstruction;
- secondary Jump;
- no measurable difference;
- failure to localize;
- failure to recover within horizon.

Direction reversal or heterogeneous effects remain valid evidence. The protocol does not preregister one monotonic direction as necessary.

## 18. Full Rerun / Checkpoint Retry as secondary engineering baselines

Where resources allow, Full Rerun and Checkpoint Retry may be added as secondary engineering comparators for:

- recurrence;
- preserved-node ratio;
- reopened node count;
- token/latency cost;
- secondary bias.

They are not required to define the core R7 scientific question and must not turn the first paper into a compute-scale competition.

## 19. Semantic boundary

R7 freezes structural evidence only.

Whether J0, a descendant, a recurrence or a recovery event is semantic C/P/R is an R8 adjudication question.

## 20. Offline implementation path

Before any real provider execution, implement and validate offline:

- persistent-field delivery ledger;

## 21. Real-run gate

A future real R7 run requires a new freeze artifact containing:

- exact C1/C2/C3 definitions and hashes;
- parent/J0 identity;
- correction payload identity/hash;
- authority/provenance condition;
- dependency-closure version;
- local reopen/recovery version;
- observation horizon and censoring rules;
- primary structural and preservation metrics;
- model/provider binding;
- repeat count;
- explicit paid authorization and spending ceiling.

This protocol authorizes no provider call.
