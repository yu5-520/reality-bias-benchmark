## 1. First group and later groups

The first group contains **seven system-layer probes × three task families × one independent natural trajectory per cell = 21 planned natural trajectories**. T1/T2/T3 are the three task families defined in v6.0; their actual file fixtures, starting repository hashes, permitted edit scopes, acceptance checks and prompt identities must be fixed before subject execution. The existing Stage-I Software Engineering release-decision fixture is historical evidence and does not silently become a T1/T2/T3 code fixture.

Do not expand this group to five repeats per cell, pool it with the historical 90 trajectories, or rerun a cell to obtain a desired C/P/R label. Keep failed, censored, healthy-preservation, null and `ENGINEERING_BLOCKED` cells visible with their original denominator and reason. A later group may be added **only after first-group freeze and synthesis**, under a new prospective R Plan version stating its new scientific question, exact cells and independent budget. An absent expected result is not itself a reason to add a group.

## 2. Stage-II evidence responsibilities

| Role | Evidence and operation | New subject execution |
| --- | --- | --- |
| R2–R4 | Simultaneous structural views of formation, propagation, retrospective return and interactions within each natural trajectory | the 21 natural trajectories only; no separate R2/R3/R4 runs |
| R6 | Trajectory-first dynamic semantic audit of source, carrier, transformation, descendant, downstream read/use, operational consequence, persistence and re-entry; include healthy and unresolved paths | none; passive on frozen raw evidence |
| R7 | External monitor localization and lineage-addressed **repair package** for an eligible, source-backed affected closure; explicit preservation and re-entry checks | package construction is offline; at most four actual local repair continuations if needed and eligible |

**No new R5 condition or R5-style authority-withdrawal validation is part of Stage II.** Historical R5 retains its Stage-I mechanism role. Without a new R5 contrast, R6 must not label natural differences as intervention-caused inertia change or target-specific intervention response. An R7 repair continuation tests the particular package and its subsequent process; it is not an R5 replication or an architecture prevalence sample.

For every natural trajectory retain the common `source → authority state → carrier → transformation → downstream exposure/read/use → decision/action consequence` evidence route. A carrier visible in input is only **exposure**, not proof of semantic adoption. R6 audits the complete first-group trajectory inventory at a defined minimum semantic level, not only structural-positive cases; detailed node-path reconstruction must retain frozen raw locators and independent support or uncertainty.

## 3. Four-continuation ceiling and repair gate

The v6.0 ceiling of **at most four additional subject continuations** is retained, but within this first group they are reserved for **R7 localized repair validation only**. The illustrative raw/compressed, memory enabled/withheld, retrieval-path and remote-artifact contrasts in v6.0 §12 are not automatic extra experiments in this execution version. If one becomes necessary for a distinct attribution question, register a later prospective plan version before running it; do not quietly consume an R7 slot or append a new condition after viewing outcomes.

An R7 candidate must first have: (1) a natural frozen parent and source-backed semantic path; (2) an addressable target ancestor/carrier; (3) a bounded affected closure; (4) an explicit set of non-target state to preserve; (5) an operator and expected observation surface fixed before continuation; and (6) a way to detect old-lineage re-entry. Record the package hash and parent hash before applying it. One applied package creates one append-only local continuation; do not repeat it to manufacture an effect. If no case passes, report **zero applied repairs** and the gate failures.

Distinguish three engineering outcomes: *package addressability*, *actual local application*, and *post-application process effect plus non-target preservation*. Constructing a repair package alone proves none of the latter two. Repair may remain architecture-specific even if observation is shared.

## 4. Day-1 handoff gate

Before any first-group subject call, freeze a machine-readable 21-cell manifest binding v6.0 + this clarification, the exact T1/T2/T3 fixtures, model/provider and limits, seven implementation/protocol versions, prompts/roles, adapter identities, native-to-common event mapping, repository code SHA and raw-output destinations. Require native evidence for source/carrier addressability, send/delivery/exposure/use distinctions, outcome and stop status, content hashes, and absence of synthetic semantic use inferred from a structural event. An official protocol version and an SDK version are distinct bindings; do not substitute one for the other.

An adapter that cannot faithfully expose its native boundary is `ENGINEERING_BLOCKED`, not replaced with an unplanned SDK or a Common Pool alias. The previous five-structure/three-domain/90–150-trajectory proposal is superseded by v6.0 and must not be merged into this execution path. Historic frozen evidence is never rewritten. These checks are preparation; they do not certify a scientific result or authorize bypassing the corresponding paid-provider spending gates.
