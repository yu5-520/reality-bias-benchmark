# Native host continuation and proposal authority

The current MCP execution path is [same-parent native MCP repair](StageII_Same_Parent_Native_MCP_Repair.md). The two separate fixtures described here remain frozen predecessor engineering evidence.

Status: offline engineering infrastructure. No autonomous repair planner, subject
model call, real repair exit or independent semantic assessment is performed.
Historical natural trajectories and studied framework protocols remain frozen.

## Host capability envelope and exact proposal authorization

`ProposalAuthorityCompiler` receives a host-retained task capability envelope
before source diagnosis. That envelope specifies original task, parent, native
application surfaces, supported field operations and action/value budgets. It
does not contain a chosen field, replacement value, correct answer or semantic
diagnosis. Task capabilities must come from the original host contract; a source
citation, visible graph node or agent explanation cannot add capabilities.

The offline archive fixture grants the host's existing application files through
`HostCheckout.write_file`, restricted to JSON leaf or exact text span operations.
Its independent current-answer capability remains limited to `/answer` on the
experiment-owned host. Foreign information stores, framework private state,
historic messages, queue, inbox, budget and original task are not repair surfaces.
No new files, arbitrary shell actions, arbitrary verification programs or native
framework operations are created by this compiler.

After a proposal, the host checks current target source witnesses, native file
versions, task/parent identity, route roles, diagnosis endpoint evidence, unknown
relationships and ordered dependencies. The exact fields, replacement values,
output versions and execution order are frozen in a separately retained
`BoundProposalAuthorization`. Native dispatch compares the complete supplied
bundle with that retained bundle before copying or writing. Editing values or
dependencies and re-sealing the payload does not widen permission. Repeated
dispatch is rejected. The actor receives no authority-building API.

The underlying historical `RoutePlanningSession` and `OfflineRouteRepairSystem`
are composed unchanged so their sealed fixtures remain reproducible. This new
dispatch wrapper is required for post-proposal exact authorization. Direct use
of the older executor with some other separately supplied host policy is not
automatically protected by this new wrapper. Python object encapsulation is an
application boundary, not an OS sandbox or protection from a hostile host caller.

Candidate meanings remain claims. Evidence integrity and permission checks do
not establish a semantic fault or repair effectiveness. The positive archive
proposal is the previous explicitly manual terminal fixture; no agent generated
it. Unit checks exercise authorized native dispatch on synthetic branches. The
archive check compiles its authorization without executing another repair.

`load_host_parent` verifies the checkpoint content address, native adapter and
framework binding, original task, native state, model-context artifact,
application manifest and every file. Queue, inbox, history, stop reason and saved
budgets must round-trip through `SoftwareHostCheckpointAdapter.load_state`.
Native history numbering must agree with the actual capture's ledger sequence.

It has 60 remaining decisions. An existing first-eligible monitor annotation
references the same native capture; that annotation is retained as an annotation,
not a separately invented checkpoint. This structural selection does not prove
the earliest unsupported semantic transition or select a scientific repair entry.

Stopped and terminal parents cannot be reopened. Remaining budget alone is
insufficient: the old terminal parent still has 28 unused decisions but is
`finalized`, and is refused. Missing native state is never filled from a later
trajectory or from a guessed task state.

## Offline continuation and external observations

`OfflineNativeContinuation` restores a fresh application copy and the exact host
state, then reuses the existing experiment-owned `_resume_host` implementation.
It starts at saved history length plus one and retains the saved budget. A fixed
`OfflineScript` is the only admitted response source; live provider callbacks
and subject execution remain disabled. The old full-trajectory graph is not
introduced into this early-parent continuation. A separate graph captures the
restored parent and actual engineering branch observations.

The passive observer records native host/application states, exact model-visible
prompts and scripted envelopes, before/after native application actions, turn
returns, terminal return, closure/censor/failure and final state. It performs no
native scheduling or application mutation. Each capture has source bytes,
checksum and a local sequence. These captures remain engineering observations;
they are not a new natural experiment, historical prefix reconstruction or proof
of cross-clock semantic order.

An intent is persisted before a scripted response is consumed. A second attempt
on the same object and a reconstructed driver at an existing output directory
are rejected. Interrupted/failed attempts retain partial state and observations
for read-only review. There is no automatic replay, budget reset, rollback or
continuation recovery from a partially consumed model turn.

The archive probe resumes the local host component for four scripted turns:
sequence 4 → 8, remaining horizon 60 → 56. The restored specialists forward
their scripted completion through the original queue/inbox behavior; the entry
agent finalizes. The observed driver release is `OFFLINE_DRIVER_RELEASE`, never
`REPAIR_AGENT_EXIT`. A synthetic script cannot unlock real independent review.

External carrier references are compared without mutation. The archive's selected
host manifest has no external references. This does not demonstrate that the
foreign MCP runtime is attached or fully restorable. The probe uses local
`HostCheckout`; it is host-component continuation infrastructure, not a full
framework-faithful MCP subject continuation. Framework-native external bindings
and prefix-safe complete planning evidence are still required.
