Date: 2026-09-17  
Status: FORWARD / R6 IDENTIFICATION CONSOLIDATION / R7 ENGINEERING IMPLICATION

## 1. Version decision

v4.5 does not add a new R stage. It consolidates the latest evidence logic into the existing program:

- R5 remains the bounded one-shot local perturbation probe;
- R6 is strengthened from a post-consumption readout into the full **System Inertia Identification** layer;
- S0/S1/S2 becomes an internal R6 specificity design rather than a quasi-independent stage;
- R7 remains the structural risk-control/localized-recovery experiment and gains an explicit, separate engineering implication: a lightweight, pluggable, content-addressed runtime integrity layer for monitoring, scouting/localization and point repair;
- R8 remains semantic CPR adjudication after structural evidence is frozen.

Historical evidence, reports, manifests, labels and semantic status remain append-only and unchanged.

This plan authorizes no scientific provider call and no paid evaluator call.

## 2. Forward research chain

```text
Natural multi-Agent process
  -> R2: observe natural Jump
  -> R3: reconstruct inheritance / propagation
  -> R4: observe retrospective / challenge / return dynamics
  -> R5: one bounded local authority-withdrawal probe
  -> R6: identify system inertia
       |- R6-A natural variability baseline
       |- R6-B carrier / inheritance identification
       |- R6-C intervention-related inertia transition
       `- R6-D target specificity (S0/S1/S2)
  -> R7: risk-bounded structural control / localized recovery
  -> R8: CPR semantic adjudication and evidence freeze
  -> R9: external robustness / independent replication
```

The core paper logic is therefore:

> **R5 perturbs. R6 identifies what actually changed, how it was carried, whether it exceeds natural variability, and whether it is target-specific. R7 tests whether that identified risk-bearing structure can be repaired locally.**

## 3. R5 — bounded local probe only

R5 has one scientific responsibility: create the smallest credible local counterfactual perturbation at a selected natural J0 and then exit.

For the established authority-withdrawal family:

`fact -> unconfirmed`

Required invariants:

- one direct experiment-origin exposure;
- no opposite factual claim;
- no replacement conclusion;
- no desired action or terminal answer;
- no Agent identity change;
- no topology or routing prescription;
- no persistent experiment-origin mutation;
- no experiment-origin reinjection after consumption;
- free downstream continuation.

R5 may document the **direct exposure window**, including local checking, rewriting, messaging, invocation or early termination.

R5 does **not** by itself establish:

- persistent system-inertia change;
- intervention effect beyond natural variability;
- target specificity;
- CPR semantic identity;
- successful control/recovery.

## 4. R6 — System Inertia Identification

R6 now contains four distinct identification responsibilities.

### R6-A — Natural Inertia Baseline

Question:

> How variable is the system when no new perturbation is applied from the same or comparable starting context?

Natural repeated continuations are not merely a limitation. They define the reference distribution/geometry against which intervention-related changes must be interpreted.

Examples of structural comparison objects:

- root-reachable event set/count;
- reach depth;
- actor transition sequence;
- branch/merge/re-entry;
- cross-Agent relations;
- path-family structure;
- state-lineage destination;
- reconvergence/censoring.

A single `A != B` realization is insufficient to establish an intervention effect when natural continuations already show large divergence.

### R6-B — Carrier / Inheritance Identification

Question:

> Through what observable carrier does prior state influence later process structure?

Candidate carriers include:

- message content plus source refs;
- shared-state field/revision;
- invocation request/result;
- inherited goal/constraint;
- evidence/provenance reference;
- final/reopen/revision state;
- Agent/stage handoff.

Evidence strength should distinguish:

1. **reachable carrier** — structurally available downstream;
2. **read/received carrier** — actually delivered/read;
3. **adopted carrier** — explicitly used/referenced in a later decision/action;
4. **inherited carrier** — produces a new state/action with source-backed dependence;
5. **propagated carrier** — the inherited state itself affects further descendants.

Structural reachability is not sufficient to claim semantic adoption.

### R6-C — Intervention-Related Inertia Transition

Question:

> After the direct experiment-origin signal has been consumed, is the downstream inertia profile distinguishable from natural variability?

The direct response window and post-consumption window must remain separate.

A useful conceptual comparison is:

```text
d(Ai, Aj) = natural variability
d(Bi, Bj) = treated-condition variability
d(Ai, Bj) = cross-condition variability
```

where `d` is a preregistered process-distance vector or frozen aggregation rule, not an after-the-fact complexity score.

No monotonic direction is required. The intervention may alter path family, transition propensity, carrier survival, re-entry or other structure without always increasing or decreasing complexity.

### R6-D — Target Specificity

Question:

> Is the post-consumption inertia response to the J0-derived target distinguishable from the generic response to making an ordinary factual item uncertain once?

Use the S namespace inside R6:

- **S0** — Natural Reference;
- **S1** — Ordinary/Matched Factual Information Downgrade;
- **S2** — J0-Targeted Escape-Derived Factual-Authority Withdrawal.

Primary contrast:

`S2 - S1`

Auxiliary contrasts:

- `S1 - S0` — generic uncertainty response;
- `S2 - S0` — total J0-targeted response.

S1 is not required to be inert.

`ONE_SHOT_TARGET_SCOPED_EPISTEMIC_STATUS_ANNOTATION`

This is a prospective specificity extension. It does not rewrite or relabel the historical R5-MID operator.

## 6. Censoring rule

Natural termination before further continuation is observed is **right-censoring**, not evidence of zero or permanent absence of inertia.

Therefore:

- no later Jump observed within a bounded terminated trajectory != permanent extinction;
- B2 not realizing the A2 O->A->I->O continuation != proof that the continuation could never regenerate;
- missing/terminated downstream opportunity must be recorded separately from negative evidence.

## 7. CPR remains semantically downstream

Process change is not equivalent to Process Reality violation.

R8 must separately adjudicate:

### C

A weaker/limited evidential state gains stronger inheritable factual authority without sufficient support, and downstream use reflects that stronger authority.

A `fact` label alone is insufficient.

### P

Scope/focus/information/Agent/tool/stage expansion exceeds the supported/authorized process boundary and materially changes the process.

One extra Agent call alone is insufficient.

### R

A prior C/P-derived deviation or descendant persists/regenerates/normalizes after a valid challenge/correction opportunity, remains source-linked to the prior deviation, and lacks sufficient new evidence to justify re-confirmation.

Same-key recurrence alone is insufficient.

## 8. R7 — scientific role

R7 asks:

> Can a source-backed, risk-bearing inertia carrier or affected dependency closure be localized and repaired while preserving unrelated process freedom?

The scientific R7 remains distinct from productization.

Core R7 conditions remain `C1/C2/C3`:

- C1 — One-Shot Free Continuation;
- C2 — Persistent Field Propagation;
- C3 — ALR Authority-Localized Recovery.

R7 success requires both:

- risk-bearing inertia reduction/localization;
- preservation of unaffected nodes/fields/branches/Agent participation/path diversity.

Whole-system suppression or target-answer forcing is not localized recovery.

## 9. R7 engineering implication — Process Integrity Protocol

The mechanism naturally supports a practical runtime layer, but this engineering profile must remain conceptually separate from the scientific R7 claim.

Desired engineering properties:

- **lightweight** — capture only the minimal process/event/provenance structure needed for tracing;
- **pluggable** — attach as middleware/sidecar/interceptor without requiring a new Agent framework;
- **non-invasive by default** — passive observation must not change normal Agent prompts, routes or outputs;
- **protocol-agnostic** — usable across MCP, A2A, HTTP/RPC, event bus, workflow + Agent and custom orchestration;
- **real-time** — content identity and lineage are registered as events occur, not reconstructed only after failure;
- **content-addressed** — state/message/event/field/revision identities can be located by stable content or revision hash;
- **localized** — recovery targets the smallest source-backed affected closure;
- **reversible/auditable** — repaired revisions retain parent/revision lineage and old-path re-entry remains observable.

Minimal engineering lifecycle:

```text
Observe
  -> register content identity
  -> reconstruct lineage
  -> detect / scout candidate breach
  -> localize carrier and affected closure
  -> point repair / localized reopen if authorized
  -> resume free execution
  -> verify old/new lineage
```

The protocol must not become a new supervisor that prescribes the normal multi-Agent topology.

## 10. Minimal runtime event interface

The engineering layer should be able to operate from a small interoperable event surface such as:

- `MessageEvent`;
- `StateEvent`;
- `InvocationEvent`;
- `EvidenceSourceEvent`;
- `RevisionEvent`.

Optional adapters may translate native framework events into this common representation.

Jump, carrier, inertia and affected-closure objects can then be derived without requiring every Agent to emit proprietary reasoning traces.

## 11. Real-time content addressing

The engineering value is not merely faster logging.

At event creation time, the system should be able to bind identities such as:

- EventHash;
- MessageHash;
- StateHash;
- FieldHash;
- SourceHash;
- RevisionHash;
- parent/lineage refs.

This enables direct queries such as:

> Which event produced this state? Which Agents read it? Which later states inherit it? Which descendants belong to the affected closure? Which old lineage remains active after repair?

Natural-language wording may change while lineage identity remains traceable.

## 12. First-paper contribution structure

The first paper should keep four contribution layers separate:

1. **Phenomenon** — terminally similar multi-Agent runs can contain materially different process histories;
2. **Mechanism** — Jump/Reality Authority can enter source-backed carriers and form inherited system inertia;
3. **Identification** — R6 distinguishes local response, carrier inheritance, natural variability, intervention-related inertia transition and target specificity;
4. **Solution** — R7 tests whether mechanism knowledge supports localized risk control/recovery and motivates a lightweight runtime Process Integrity Protocol.

Semantic CPR identity remains a separately adjudicated layer, not something inferred from any structural difference.
