# R7 System Structure Position v0.3

Date: 2026-09-17  
Status: FORWARD POSITION  
Predecessor: `docs/R7_system_structure_position_v0.2.md`

## 1. Continuity

The earlier R7 system-structure direction remains valid. Free Routing vs Structured Routing was not a wrong research question.

The v0.3 refinement clarifies **what the structured condition is for** in the first-paper mechanism chain.

It is not primarily a universal architecture comparison. It becomes the structural mechanism by which active ALR can trace and repeatedly repair a risk-bearing field lineage after a Jump has been localized.

## 2. Two structural roles

### Natural/free process structure

The natural Arena remains free-routing under its common experimental interfaces. Agent ordering and realized topology are not prescribed by active ALR.

### Recovery structure

After a source-backed risk-bearing Jump/lineage is selected under a frozen R7 protocol, ALR may establish a temporary structured recovery subgraph over the affected dependency closure.

This is **recovery routing**, not a permanent production workflow.

## 3. Why structured routing matters

A one-shot field correction may alter a path, but system inertia can already be distributed across:

- later state;
- messages;
- Agent activations;
- invocation history;
- descendant fields;
- retrospective/re-entry paths.

Therefore a controllability test requires sustained structural feedback that can follow revised field state through downstream carriers.

## 4. Active ALR loop

```text
free routing
  -> localize J0 / risk-bearing field lineage
  -> derive affected / preserved scope
  -> activate structured recovery routing
  -> repair field revision
  -> propagate through affected scope
  -> observe residual / recurrence / secondary Jump
  -> re-repair where preregistered conditions require
  -> release
  -> free routing resumes
```

The loop is summarized as:

**Locate -> Structure -> Repair -> Propagate -> Observe -> Re-repair -> Release**

## 5. Field-level rather than whole-Agent contamination

The preferred recovery object is a field/revision lineage, not an entire Agent by default.

An Agent may contain both affected and unaffected work. The affected set should expand only through source-backed dependency evidence.

This allows ALR to preserve unrelated successful structure while revising contaminated descendants.

## 6. Dynamic rather than fixed structured sequence

The historical v0.1 structured orchestration sequence remains preserved as historical/engineering evidence.

Forward active ALR should not assume that every recovery case follows the same fixed Agent sequence. The recovery topology should be derived from the realized affected lineage under the frozen routing/recovery policy.

Different J0 anchors may therefore produce different recovery subgraphs.

## 7. Control objective

R7 does not aim to make all processes identical.

It asks whether structured recovery can:

- localize risk-bearing inertia;
- make revision lineage traceable;
- control field-level propagation;
- contain/reduce/redirection/recover risky descendants;
- preserve unaffected nodes, fields, branches and non-risk path diversity;
- release the system back to free routing when a preregistered condition is met.

## 8. Architecture variables retained from v0.2

The broader system-structure variables remain valid research dimensions:

- routing ownership;
- topology density;
- stage boundary placement;
- context continuity/reset/compression;
- dynamic invocation surface;
- proposal/commit separation;
- Agent count;
- shared-state visibility.

They may become later boundary-condition experiments, but they must not be conflated with the core ALR recovery treatment unless explicitly preregistered.

## 9. Relationship to R5/R6

```text
R5: one-shot local perturbation
  -> path reorganization / perturbability

R6: observe downstream Jump/inheritance/return dynamics
  -> post-reorganization system inertia

R7: sustained lineage-aware structural feedback
  -> controllability / localized recovery of risk-bearing inertia
```

R5, R6 and R7 remain analytically distinct even when one evidence family informs the next.

## 10. Measurement requirement

All R7 comparison arms must retain materially equivalent passive observability. Active ALR is the treatment; basic evidence capture must not be treatment-specific.

R7 reports both:

- risk-control outcomes;
- freedom-preservation outcomes.

Reduced activity alone is not sufficient.
