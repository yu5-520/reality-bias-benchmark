# Cross-Domain Case Progression Contract v0.1

Date: 2026-09-18  
Status: FORWARD / FIRST-ROUND CASE CONTROL

## 1. Purpose

This contract defines how one frozen natural trajectory may advance from observation into R5/R6/R7 without replaying the historical ecommerce method-development path.

The unit is a **source-bound case**, not a domain-wide assumption.

## 2. State machine

```text
NATURAL_FROZEN
  -> STRUCTURAL_CANDIDATE
  -> AWAITING_LOCALIZED_SEMANTIC_AUDIT
  -> [eligible] ELIGIBLE_R5_ATOMIC_PROBE
  -> [separate authorization] R5_PROBE_FROZEN
  -> R6_DESCENDANT_INERTIA_DERIVED
  -> [complete lineage] COMPLETE_FOR_AUTHORIZED_REPAIR
  -> [separate authorization] R7_REPAIR_FROZEN
  -> POST_REPAIR_WATCH_FROZEN
```

Alternative terminal states:

- `NO_QUALIFYING_NATURAL_STRUCTURE`;
- `NOT_ELIGIBLE_R5`;
- `LINEAGE_GAP_BLOCKS_REPAIR`;
- `R7_NOT_RUN`.

These are valid scientific outcomes.

## 3. Natural-case identity

Every case must bind:

- first-round ID;
- domain ID;
- source run ID;
- source wave evidence-batch hash;
- exact parent snapshot / event boundary;
- candidate ref;
- content address;
- domain/task/Agent-pool hashes;
- execution code SHA.

A later case branch never rewrites the natural source trace.

## 4. Structural candidate interface

Deterministic structural scouting may nominate:

- Repair Anchor candidate;
- content address;
- source writer/event;
- pool-visibility observations;
- downstream structural closure candidate.

It may not nominate:

- semantic truth;
- CPR label;
- problematic authority;
- R5 eligibility;
- repair completeness.

## 5. Localized semantic audit interface

The append-only semantic audit must resolve, where evidence permits:

- source proposition and source status;
- transformed proposition(s);
- read/adoption relation;
- decision/action dependence;
- authority relation;
- competing interpretation;
- selected target semantic identity.

The audit output may set scientific eligibility such as `ELIGIBLE_R5_ATOMIC_PROBE`, but does not authorize execution.

## 6. R5 interface

Required source-bound inputs:

- exact natural parent;
- selected semantic target/content address;
- one atomic authority-withdrawal operator;
- exact direct exposure count = 1;
- reinjection count = 0;
- persistent experiment-origin mutation = false;
- fixed observation continuation.

The R5 branch is a controlled continuation of the frozen natural case.

## 7. R6 interface

R6 consumes frozen R5 evidence and derives separately:

- direct/local response;
- carrier visibility;
- downstream read/adoption;
- semantic relation propagation;
- post-consumption inertia;
- process topology;
- natural/random variation where matched evidence exists;
- affected semantic-lineage evidence.

R6 must not promote graph reachability or literal recurrence into semantic inheritance.

## 8. Repair completeness interface

The Repair Gate requires:

- exact Repair Anchor;
- Semantic Lineage Package;
- EvidenceSupportedAffectedClosure;
- compatibility partition;
- source/authority/pool history;
- no blocking `LINEAGE_GAP`.

Output status may be:

- `COMPLETE_FOR_AUTHORIZED_REPAIR`;
- `LINEAGE_GAP_BLOCKS_REPAIR`;
- `NOT_REPAIRABLE_WITH_CURRENT_EVIDENCE`.

The gate does not authorize R7.

## 9. R7 interface

Replication domains use only the current final operator family:

`Semantic Lineage Package Repair -> invalidate incompatible descendants -> reopen dependent recipients -> preserve compatible state -> selective recompute -> bind new lineage`

Historical replay-based target regeneration is forbidden as a replication step.

R7 must record:

- old and new revision identities;
- invalidated descendants;
- reopened recipients;
- recomputed refs;
- preserved compatible objects;
- old-lineage re-entry;
- post-repair watch.

## 10. Authorization separation

Natural subject authorization does not authorize R5.

R5 authorization does not authorize R7.

R7 authorization does not authorize R8/CPR adjudication.

Every active stage is case-specific and append-only.

## 11. Cross-domain rule

The same interface applies to ecommerce, finance, supply_chain and software_engineering.

The semantic target is never pre-assigned by domain analogy. Each target must arise from that domain's own frozen natural evidence.

This prevents the cross-domain replication from becoming a forced search for ecommerce-shaped objects.
