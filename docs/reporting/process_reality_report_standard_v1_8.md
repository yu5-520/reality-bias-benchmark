# Process Reality Report Standard v1.8

Date: 2026-09-20  
Status: **FORWARD ACTIVE / SEMANTIC-TRAJECTORY-FIRST**  
Predecessor: `RB-PROCESS-REALITY-REPORT-STANDARD-v1.7`

Historical reports remain immutable.

## 1. Core report chain

Forward reports must use:

`Frozen Evidence -> Complete Actual Agent Route -> Semantic Lineage Overlay -> Node/Edge Semantic Audit -> Typical Contrast -> Supporting Structural Data -> Aggregate Counts -> Claim Boundary -> Provenance`

Structural data remain the factual substrate.

**Semantic audit is the primary interpretive content.**

## 2. Report-generation gate

A forward report requires a machine-readable:

`RB-PROCESS-REALITY-REPORT-EVIDENCE-BUNDLE-v0.1`.

Major semantic cases must bind validated:

`RB-SEMANTIC-TRAJECTORY-AUDIT-v0.1`

records.

If complete-route semantic evidence is absent, report status must be:

`BLOCKED_MISSING_SEMANTIC_TRAJECTORY_EVIDENCE`.

## 3. Primary visual center

The primary case visual is:

`TIME_ALIGNED_ACTUAL_AGENT_ROUTE_WITH_SEMANTIC_LINEAGE_OVERLAY`.

It must show:

- all actual executed Agent nodes;
- actual execution/handoff order;
- target-relevant semantic nodes as an overlay;
- semantic relation edges;
- authority/status changes where relevant;
- intervention boundary and direct-stimulus end where applicable;
- finalization/censoring.

An all-to-all structure graph, aggregate topology chart or summary count chart may support the report but may not replace the primary trajectory visual.

## 4. Full-route rule

A report may not show only the target lineage while hiding other executed Agent nodes.

Irrelevant nodes remain visible and are marked as outside the target lineage.

This prevents the report from presenting a hand-selected semantic path as though it were the whole run.

## 5. Semantic-content rule

For every major semantic transformation, report:

- semantic before;
- semantic after;
- semantic delta;
- producing Agent;
- reading/adopting Agent;
- evidence refs.

Labels such as `transformation`, `adoption`, `carrier` or `inertia` without concrete semantic content are insufficient.

## 6. Primary-domain rule for the current first-round report family

Primary held-out experiment domains are:

- finance;
- supply_chain;
- software_engineering.

Ecommerce is excluded from the primary first-round experiment evidence.

If ecommerce is mentioned, it must be clearly labeled historical method-development context and may not serve as a primary typical case or report denominator.

## 7. R2-R4 report rule

A cross-domain R2-R4 phenomenon report must contain at least one complete actual route from each held-out domain:

- finance;
- supply_chain;
- software_engineering.

The examples are illustrative mechanism evidence, not the statistical denominator.

Example selection reason must be declared and must not be outcome cherry-picking.

## 8. R5 report rule

Canonical geometry remains:

`N0 existing + R5-I once`.

At least one complete N0-versus-R5-I realized contrast must be shown.

If heterogeneous or opposite realized trajectories are used to motivate stochastic boundaries, show them before aggregate summary.

A single realized contrast does not establish a directional treatment law.

## 9. R6 report rule

If the report claims:

`post-stimulus persistence != System Inertia`

it must show at minimum:

- one complete stronger-System-Inertia candidate route;
- one complete non-inertia / re-anchored comparator route;
- both semantic lineage overlays;
- the difference in semantic ancestry.

A table containing only `4/29` versus `25/29` is insufficient.

## 10. Structural data role

Structural evidence remains mandatory, including as applicable:

- turns/calls;
- messages/invocations;
- state writes;
- hashes;
- lineage edges;
- reach/depth;
- branch/merge;
- re-entry;
- censoring;
- costs.

These establish factual substrate and support semantic interpretation.

They may not replace semantic trajectory evidence.

## 11. Aggregate-count rule

Aggregate counts come after major realized paths.

Counts must be derived from case-level records, not preassigned uniform semantic outcomes.

Examples do not define denominators.

## 12. Process / endpoint separation

`same endpoint != same process`.

Reports must distinguish terminal convergence from semantic ancestry and route-level process.

## 13. Claim-status discipline

Use:

`DIRECTLY_EVIDENCED`, `SUPPORTED`, `SUPPORTED_CANDIDATE`, `UNRESOLVED`, `NOT_ESTABLISHED`, `NOT_OBSERVED`, `CONTRADICTED`, `NOT_ADJUDICATED`.

## 14. Required opening block

Every report states:

- report role;
- primary question;
- evidence sets/workflows;
- semantic audit method/version;
- main bounded result;
- claim boundary;
- reporting standard;
- raw evidence mutation;
- new subject/provider/evaluator calls;
- CPR status.

## 15. Recommended section order

1. Scope and Evidence Binding
2. Experiment Accounting
3. Domain / Target / Condition Identity
4. Typical Complete Actual Agent Routes
5. Semantic Lineage Overlays and Transformation Ledgers
6. Typical Positive / Negative or Natural / Intervention Contrasts
7. Supporting Structural / Carrier Measurements
8. Aggregate Case Taxonomy / Counts
9. Process / Terminal Outcome Separation
10. Directly Evidenced
11. Supported Candidates / Open Questions
12. Not Established / Not Adjudicated
13. Interpretation Boundary
14. Evidence Provenance / Freeze Boundary

## 16. Authorization boundary

A report authorizes no subject run, provider/evaluator call, repair action or semantic adjudication.
