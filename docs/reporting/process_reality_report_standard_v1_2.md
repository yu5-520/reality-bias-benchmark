# Process Reality Report Standard v1.2

Status: **FORWARD ACTIVE REPORTING STANDARD**  
Language: **English only**  
Predecessor: `RB-PROCESS-REALITY-REPORT-STANDARD-v1.1`

## 1. Compatibility

v1.2 preserves historical v1.0/v1.1 reports. No frozen report is rewritten.

The new reporting hierarchy is:

`raw evidence -> Jump/lineage -> local response -> R6 natural baseline -> carrier/inheritance -> intervention-related post-consumption inertia -> target specificity -> R7 localized recovery -> R8 semantic adjudication -> terminal outcome separately`

## 2. Core separation rule

The following must never be collapsed into one claim:

- local/direct response;
- carrier/inheritance evidence;
- natural variability;
- intervention-related inertia transition;
- target specificity;
- CPR semantic identity;
- localized recovery/control.

A report may support some while leaving others unresolved.

## 3. R6 System Inertia Identification Report

### Purpose

Report the full R6 identification chain rather than only whether downstream topology differs.

### Required sections

1. Scope and frozen evidence binding
2. J0/source-root evidence
3. Direct exposure/local-response window
4. R6-A natural inertia baseline
5. R6-B carrier/inheritance evidence
6. R6-C post-consumption intervention-related inertia transition
7. Process-distance/vector comparison
8. Censoring and natural termination
9. R6-D target specificity if S data exist
10. Terminal outcome separately
11. Claims supported
12. Claims unresolved/not established
13. Interpretation boundary
14. Evidence provenance

### R6-A rule

Natural repeated continuation variability must be shown explicitly. Large natural variation is not hidden as noise.

A single A/B difference must not be labeled an intervention effect when natural A/A variation is comparable and no further identifying evidence exists.

### R6-B rule

Carrier evidence should use the highest supported level:

- `REACHABLE_CARRIER`
- `DELIVERED_OR_READ_CARRIER`
- `ADOPTED_CARRIER`
- `INHERITED_CARRIER`
- `PROPAGATED_CARRIER`

Graph reachability alone must not be described as semantic adoption.

### R6-C rule

The treated inertia window begins after the direct experiment-origin signal is consumed.

Immediate T9-like activity may be reported, but it cannot alone establish post-consumption system-inertia transition.

### Censoring rule

Natural early termination is right-censoring. It is not zero inertia, permanent extinction or permanent recovery.

## 4. R6 Target-Specificity Report

The S triad is an internal R6-D design.

Current forward labels:

- `S0_NATURAL_REFERENCE`
- `S1_MATCHED_OR_ORDINARY_FACTUAL_INFORMATION_DOWNGRADE`
- `S2_J0_TARGETED_ESCAPE_DERIVED_AUTHORITY_WITHDRAWAL`

Primary contrast: `S2 - S1`.

Required sections:

1. Scientific question
2. Frozen source/common-context binding
3. S1 outcome-blind selection integrity
4. Exact S1/S2 target binding
5. Mechanical-equivalence audit
6. Exposure/consumption/reinjection/persistent-mutation audit
7. Local responses by arm
8. Carrier/inheritance evidence by arm
9. Natural baseline
10. Post-consumption inertia profiles
11. `S1-S0` generic uncertainty contrast
12. `S2-S0` total J0-targeted contrast
13. `S2-S1` target-specificity contrast
14. Censoring
15. Terminal outcome separately
16. Claims supported/weakened/unresolved
17. Evidence provenance

S1 is not required to be inert.

## 5. Exact-source atomic target notation

Where the v0.2/v0.3 atomic specificity design is used, the report must disclose that it is a prospective follow-up and not an exact replay of historical R5-MID container-level intervention.

Current frozen prospective targets:

- S1: `public_context.products.C.gross_margin_pct = 35`
- S2: `shared_state.inventory_stockout_assessment_v1.A.preliminary_stock = 1520`

S2 source origin: `preliminary_unreconciled`; acquired container authority at J0: `fact`.

## 6. R7 Localized Risk-Control / Recovery Report

### Purpose

Test whether an R6-identified risk-bearing carrier/closure can be localized/recovered while preserving unrelated process freedom.

### Required sections

1. R6 target/carrier/closure binding
2. C1/C2/C3 condition definitions
3. semantic-correction equivalence audit
4. passive-observability equivalence audit
5. affected/preserved partition
6. C1 endogenous inertia
7. C2 experiment-maintained persistence
8. C3 ALR localized recovery
9. risk-control outcomes
10. freedom-preservation outcomes
11. proposal-versus-realization evidence
12. content/revision lineage
13. residual/re-entry/recurrence evidence
14. engineering cost metrics if available
15. terminal outcome separately
16. interpretation boundary
17. evidence provenance

R7 success requires both risk reduction/localization and preservation of unrelated structure.

Whole-system suppression is not equivalent to localized recovery.

## 7. Process Integrity Engineering Profile

An engineering appendix/report may describe the proposed runtime layer, but must label it clearly as **engineering implication**, not as an already validated scientific result.

Engineering design targets:

- lightweight;
- pluggable;
- non-invasive/passive by default;
- protocol-agnostic;
- real-time;
- content-addressed;
- lineage-aware;
- localized recovery;
- auditable revisions.

Suggested event identities:

- EventHash;
- MessageHash;
- StateHash;
- FieldHash;
- SourceHash;
- InvocationHash;
- RevisionHash;
- ClosureHash.

A passive observer must not prescribe Agent order, tool choice or topology.

## 8. Process-distance reporting

Prefer a multidimensional vector until a scalar has been preregistered and validated.

Report dimensions such as:

- event-set distance;
- edge-set distance;
- actor-set/sequence difference;
- reach/depth difference;
- branch/merge/re-entry difference;
- cross-Agent difference;
- path-family difference;
- state-lineage destination difference;
- reconvergence difference;
- carrier-survival difference.

Do not invent a post-hoc complexity score to rescue a desired interpretation.

## 9. CPR reporting boundary

A structural report may nominate CPR candidates but may not adjudicate them unless a separate R8 review object exists.

Minimum semantic cautions:

- `fact` label alone != C;
- extra Agent/tool call alone != P;
- same-key recurrence alone != R.

## 10. Evidence status labels

Use explicit status labels where applicable:

- `RAW_EVIDENCE`
- `STRUCTURAL_DERIVATION`
- `LOCAL_RESPONSE_ONLY`
- `R6_CARRIER_EVIDENCE`
- `R6_POST_CONSUMPTION_INERTIA_EVIDENCE`
- `R6_TARGET_SPECIFICITY_EVIDENCE`
- `R7_LOCALIZED_RECOVERY_EVIDENCE`
- `ENGINEERING_ONLY_NOT_SCIENTIFIC_EVIDENCE`
- `NOT_ADJUDICATED`
- `ADJUDICATED_APPEND_ONLY`
- `CENSORED_OR_UNRESOLVED`

## 11. Figure grammar

Maintain v1.0/v1.1 publication-oriented grammar:

- time left-to-right;
- causally salient handoffs rather than spaghetti graphs;
- source refs for long dependencies;
- separate lanes for execution, messages/handoffs, state, carrier/lineage, intervention/recovery;
- terminal outcome visually separated from process mechanism.

For R6 identification figures, include natural-baseline and carrier panels.

For R7 figures, show affected versus preserved closure and revision lineage.

## 12. Provenance requirements

Where available, include:

- workflow/run ids;
- source parent hash;
- raw trace hash;
- evidence batch hash;
- plan hash;
- execution code SHA;
- measurement/analysis contract ids;
- field-selection record hash;
- operator/envelope hashes;
- carrier/closure derivation version;
- affected-closure hash;
- prior/repaired revision hashes;
- report-standard version.

## 13. Integrity constraints

Reports must not:

- mutate frozen evidence;
- invent missing events;
- silently exclude runs;
- convert censoring into absence;
- convert reachability into adoption;
- convert local response into inertia by default;
- convert path difference into condition effect without natural-baseline comparison;
- convert specificity into CPR truth;
- convert engineering readiness into scientific efficacy;
- relabel historical A/B evidence as S conditions;
- alias R6 S conditions to R7 C conditions.

## 14. Authorization boundary

A report never authorizes a provider run, evaluator run, semantic adjudication or active recovery operation.
