# Process Reality Report Standard v1.5

Status: **FORWARD ACTIVE / PROCESS REALITY v5 WHOLE-PROCESS PROFILE**  
Date: 2026-09-18  
Predecessor: \`RB-PROCESS-REALITY-REPORT-STANDARD-v1.4\`

Historical reports remain immutable.

## 1. Core reporting chain

Forward v5 reports preserve:

\`Frozen Evidence -> Structural Indexing/Scouting -> Localized Semantic Audit -> Claim-Boundary Interpretation\`

When a controlled probe or repair exists, append:

\`-> Driver/Control-Surface Comparison -> Recovery Interpretation\`

The system is a measuring/scouting instrument, not a semantic judge.

## 2. Mandatory concept separation

Forward reports must distinguish:

\`semantic genesis != semantic transformation != structural support != stable-pool entry != structural exposure\`

and:

\`Detection Surface != Trace Root != Intervention Surface\`

A legacy Jump/J0 may be named as a historical identifier but must not be silently promoted to any v5 object.

## 3. Default report identity block

Include, as applicable:

- reporting-standard version;
- v5 theory/plan version;
- evidence-set identity;
- raw-evidence freeze status;
- structural-index/scout version;
- semantic-audit version/status;
- provider/evaluator status;
- controlled-probe status;
- recovery status;
- CPR status;
- report date/language.

## 4. Default section order

1. Scope and Evidence Binding
2. Run / Batch / Parent Identity
3. Natural Process Evidence
4. Structural Scout Output
5. Unstable-Information and Transformation Audit
6. Structural Support Evidence
7. Stable Shared Pool / Direct Consumption Evidence
8. Structural Exposure Evidence
9. Driver-Probe Evidence, if any
10. Upstream Trace / Downstream Closure
11. Intervention-Surface Analysis, if any
12. Recovery Evidence, if any
13. Optional Robustness Modules
14. Process / Terminal Outcome Separation
15. Directly Evidenced
16. Supported Candidates / Open Mechanism Questions
17. Not Established / Not Adjudicated
18. Interpretation Boundary
19. Evidence Provenance / Freeze Boundary

Sections that do not apply should be marked not run/not applicable rather than filled with invented content.

## 5. Evidence tables first

Prefer evidence tables binding:

- object/claim;
- source proposition/status;
- event/state/field refs;
- structural fact;
- semantic audit result;
- relation;
- claim status;
- boundary/alternative interpretation.

## 6. Structural Support and pool reporting

A Structural Support claim must state what system structure provides reusable support.

A Stable Shared Pool claim must state:

- where the addressable state resides;
- whether later Agents directly consume it;
- source/pool epistemic status where observable;
- whether original relay is still required.

"Stable" must never be used as shorthand for true/confirmed.

## 7. Structural Exposure reporting

Exposure is a scouting object.

Reports should state:

- exposure candidate rule;
- candidate region;
- audit window reduction where measured;
- whether the exposure mapping is semantic-audit supported.

Exposure must not be called origin merely because it is easy to detect.

## 8. Driver-probe reporting

For R5-style probes, separate:

- source-level response;
- support-level response;
- pool-level response;
- descendant/constraint response;
- terminal outcome.

A weak source-level response does not automatically prove structure-driven causality.

## 9. R6 reporting

R6-style reports should identify, where supported:

\`source -> transformation -> support -> pool -> exposure -> descendants\`

and separately report:

- detection surface;
- trace root;
- candidate/selected intervention surface.

Historical natural-variability/carrier/specificity modules may appear as optional robustness, not mandatory report geometry.

## 10. R7 reporting

R7 reports preserve:

- EvidenceSupportedAffectedClosure;
- MechanicallyRequiredReplayDependencies;
- RepairClosure;
- selected intervention surface;
- preserved structure;
- revision identities;
- residual/re-entry evidence;
- release condition.

Whole-system suppression is not localized success.

## 11. Historical identifier compatibility

Legacy names such as \`J0\`, \`Jump\`, \`S2_J0_TARGETED_ESCAPE_DERIVED_AUTHORITY_WITHDRAWAL\` and R6-A/B/C/D remain unchanged when referring to frozen evidence.

A report may add a v5 mapping only as append-only interpretation with explicit status.

## 12. Optional robustness

S0-S4 specificity, matched controls, re-Jump telemetry, extra reviewers and cross-model/domain replication are reported only when run or materially relevant.

Their absence from a v5 Whole-Process Run is not a reporting defect.

## 13. Process and terminal outcome

Terminal correctness/reward/task completion remain separate from process-reality claims.

## 14. Claim-status discipline

Use:

- DIRECTLY_EVIDENCED
- SUPPORTED / OBSERVED
- SUPPORTED_CANDIDATE
- UNRESOLVED
- NOT_ESTABLISHED
- NOT_OBSERVED
- CONTRADICTED
- NOT_ADJUDICATED

Do not convert candidate localization into causal truth.

## 15. Close-out

Every substantive report closes with:

1. Directly Evidenced
2. Supported Candidates / Open Questions
3. Not Established / Not Adjudicated
4. Interpretation Boundary

## 16. Authorization

Reports authorize no subject run, evaluator call, semantic adjudication or active repair.
