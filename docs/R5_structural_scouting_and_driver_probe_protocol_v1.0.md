# R5 Structural Scouting and Driver-Probe Protocol v1.0

Date: 2026-09-18  
Status: FORWARD v5 / NO SUBJECT EXECUTION AUTHORIZATION

## 1. R5 role

R5 is not defined by one perturbation.

R5 has two roles:

1. **Structural Scouting** — find bounded regions where semantic audit is worth paying for.
2. **Driver Probing** — when justified, apply a minimal manipulation to test whether downstream persistence still depends on the source-level information state or on already materialized structure.

## 2. Scouting

Default path:

\`all recorded events -> structural scout -> candidate region -> localized semantic audit\`

The scout may use:

- field/state provenance;
- direct shared-state consumption;
- cross-actor reuse;
- dependency lineage;
- action/constraint descendants;
- re-entry;
- authority/status mismatch;
- content/revision identities.

It must not assign CPR.

## 3. Driver hypotheses

Allowed interpretation families include:

- \`SOURCE_INFORMATION_DEPENDENT\`
- \`DERIVED_SEMANTIC_DEPENDENT\`
- \`STRUCTURE_SUPPORTED\`
- \`MIXED_OR_UNRESOLVED\`

These are not inferred from one metric.

## 4. Historical one-shot operator

The existing \`fact -> unconfirmed\` one-shot authority withdrawal remains valid historical evidence and one forward probe family.

It preserves the value and tests whether the epistemic-status change reaches later process structure.

Non-response does not by itself prove full structural independence.

## 5. Future operator families

Any future operator must be separately frozen.

Candidate families:

- source status withdrawal;
- dependency invalidation;
- descendant semantic withdrawal;
- pool-entry revision;
- action-constraint revision.

## 6. Handoff to R6

R5 should hand R6:

- detection surface;
- candidate source/root;
- candidate support/pool refs;
- downstream candidate closure;
- driver-response evidence;
- unresolved coupling questions.

## 7. Authorization

No new provider/evaluator call is authorized.
