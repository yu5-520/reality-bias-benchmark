# Reality Bias Research Plan v5.3 — Domain Probability / Case Structure Separation

Date: 2026-09-19  
Status: FORWARD METHODOLOGICAL CORRECTION / NO NEW R STAGE / NO NEW SCIENTIFIC RUN AUTHORIZATION  
Predecessor: `docs/R_Plan_v5.2.md`

## 1. Main correction

v5.3 preserves the v5.2 separation between theory/mechanism, engineering recovery and semantic closure, and adds one mandatory scientific boundary:

`domain-level probability != case-level structure != fixed-parent local sensitivity`

The three objects use different denominators and answer different questions.

## 2. Probability layer

The probability unit is the **domain-environment trajectory population**.

A frozen domain environment includes the domain task family, Agent responsibilities, runtime, model/provider configuration and observation protocol. The probabilistic model is allowed to produce naturally different trajectories inside that environment.

The probability question is:

`P(phenomenon class | frozen domain environment)`

The current three-domain first round is already the probability experiment:

- finance: 30 natural trajectories;
- supply_chain: 30 natural trajectories;
- software_engineering: 30 natural trajectories.

R2/R3/R4 are the main natural-trajectory observation views for this layer.

## 3. Structure layer

Once a qualifying natural case appears, the scientific unit changes to a **source-bound realized case**.

The structural question is:

`what information obtained what role -> through which carrier -> read by whom -> adopted how -> constrained what -> persisted how`

R5 and R6 do not re-estimate domain probability.

## 4. R5

R5 remains a minimal case-level probe.

A probe may perturb one source/authority condition once and observe the realized continuation.

R5 does not require the exact continuation to reproduce frequently.

## 5. R6

R6 is a passive case-level mechanism-identification stage over already-frozen natural/R5 evidence.

Entering R6 does not require an additional provider run.

R6 derives, where evidence permits:

`source -> carrier/support -> downstream read -> semantic adoption -> decision/action effect -> post-stimulus persistence -> affected lineage`

A realized structure may be scientifically analyzed even if another stochastic repeat takes a different path.

## 6. System Inertia

System Inertia has two distinct claim units:

- **CASE_LEVEL_SYSTEM_INERTIA** — a realized carrier/adoption/persistence structure in one evidence-bound case;
- **DOMAIN_LEVEL_INERTIA_OCCURRENCE_RATE** — how often such a structure appears across natural trajectories in a domain environment.

The second must never be inferred from fixed-parent repetition.

## 7. Fixed-parent repetition

Repeated runs from one frozen parent are reclassified as:

`SUPPLEMENTARY_LOCAL_CONDITIONAL_SENSITIVITY`

They may estimate:

`P(exact local phenotype | same frozen parent, same local perturbation)`

They must not:

- define domain-level phenomenon probability;
- become a prerequisite for entering R6;
- become a prerequisite for entering R7;
- erase a recorded carrier/read/adoption/persistence chain when one exact phenotype does not recur.

## 8. R7

R7 remains the engineering/control stage.

Its gate is case-level lineage completeness and repairability:

- evidence-supported affected lineage;
- repair anchor;
- compatibility partition;
- no blocking lineage gap;
- explicit recovery operator;
- separate authorization.

High fixed-parent recurrence is not required.

## 9. R8/R9

R8 remains semantic interpretation/CPR closure over frozen evidence.

R9 remains supplementary reviewer/model/domain robustness and generalization.

## 10. Cross-domain wave-4 correction

The supply-chain wave-4 R5 branch contains a recorded carrier/read/adoption/persistence chain after the one-shot authority-status exposure disappears.

That chain is valid R6 structural evidence.

The later eight-pair fixed-parent experiment remains frozen evidence but is reclassified as supplementary local conditional sensitivity. Its low recurrence of one exact terminal phenotype does not negate the realized structure and does not define supply-chain domain probability.

R7 eligibility for this case must therefore be reassessed from lineage completeness, not from fixed-parent recurrence.

## 11. Evidence chain

Forward chain:

`domain environment -> natural trajectory population -> probability/distribution audit`

then, for a selected case:

`natural case -> localized semantic audit -> optional R5 probe -> passive R6 structure -> lineage completeness gate -> optional R7 repair -> R8 semantic closure`

## 12. Frozen evidence policy

No raw evidence, historical manifest, executed workflow artifact or content hash is rewritten.

v5.3 changes only forward interpretation and stage responsibility.

## 13. Authorization

This plan authorizes no provider call, paid evaluator, R7 repair or CPR adjudication.
