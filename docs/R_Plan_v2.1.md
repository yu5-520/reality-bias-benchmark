# Reality Bias 研究总规划

版本：R Plan v2.1  
日期：2026-09-15  
研究主题：Reality Bias × Authority Penetration × Multi-Agent Dynamics

## 1 规划决策与适用范围

本规划把 R2、R3、R4 定义为同一自由协作实验结构上的事件层、关系层和闭环层。三层共享运行引擎与原始证据，随运行同步留痕，随后异步审计；编号不代表必须顺序执行三套主体实验。某条轨迹可以同时具有三层研究价值，而各层结论可以在不同时间成熟。

底层工作假设是：模型产生推断或提案，经系统接口改变具有执行效力的状态，下游节点读取或继承该状态，进而产生后续行为。单次转换、跨事件传播与反馈闭环，是这套结构在不同观察尺度上的候选表现。该统一解释仍需可证伪的证据，不预设所有循环或 Agent 失败均属于 Reality Bias。

v2.1 在 v2.0 基础上增加一个成本与方法学分层：**基础观测与上限观测分开**。基础层使用固定观察窗口建立可比较、可复现的测量地基；上限层只在基础稳定后，以有限循环预算 K 检验反馈持续、扩散或增强。上限层不是默认扩样路径。

第一篇继续聚焦发生、穿透、传播、循环、控制和恢复，不加入人类受试研究或 Z 的 Change Authority。原 v1.0 中未经校准的发表概率、固定周期与固定扩样数量不再作为计划依据；预算与样本量由测量质量、试点方差和具体研究问题决定。

## 2 R0 到 R9 的结构分工

| 编号 | 研究职责 | 产物或证据门槛 |
| --- | --- | --- |
| R0 | 理论合同与版本治理 | 可判别定义、边界反例、变更记录 |
| R1 | 理论与测量压力测试 | 正常协作和偏差可区分，反例有明确处理 |
| R2 | 事件层审计 | 推断、尝试执行与实际生效可区分，机制与权限路径分别编码 |
| R3 | 关系层审计 | 定位来源、读取和继承关系；区分时序相关与因果影响 |
| R4 | 闭环层审计 | 识别反馈候选，检验循环维持、自增强与来源遮蔽 |
| R5 | 控制与风险迁移 | 实际干预后继续运行，比较单维、双维和完整权限控制 |
| R6 | 局部恢复 | 比较完整重跑、检查点重试和 ALR 的恢复、复发与成本 |
| R7 | 泛化与测量稳健性 | 主体模型和领域泛化，与评审模型一致性分别检验 |
| R8 | 复现冻结 | 全程增量固定数据、代码、模型、规则和分析版本 |
| R9 | 论文论证 | 每个主张绑定相应证据等级与适用边界 |

R2 至 R4 可以对同一批轨迹独立或并行审计。R5、R6 在共享环境上增加干预和恢复条件，需要新的实际运行；旧轨迹的静态回放不能替代阻断后的行为证据。R0、R1、R8 贯穿研究，不在某次通过后停止治理。

## 3 同步记录与异步审计

同步记录指与执行事件同步保存证据，不要求 Agent 同时运行。默认链路为准备任务、主体运行、原始证据保存、完整性校验、客观统计、评审材料导出，最终进入 RUN_COMPLETE_PENDING_REVIEW 或其他明确的运行状态。

异步审计指审计不阻塞主体实验，不向冻结轨迹反馈，也不触发主体重采样。同一证据批次可以追加多份人工或模型意见，事件、关系、闭环三层各自具有待审、部分已审、已审和争议状态。NOT_ADJUDICATED 不能替换为零偏差。

系统自动确定谁实际执行、何时读到消息、哪些状态发生变化。是否属于 C/P/R、调用是否必要、来源是否足以授权、贡献是否影响决策，由规则和语义审计共同判定。评审材料覆盖全部适用事件，通过引用去除重复内容，并可按索引展开原始证据。

多评审者先独立判断，不查看其他人的结论；分歧汇总与裁决另存记录。多数票和多模型一致性不等于真值。运行中的 reviewer 或 auditor 是主体参与者，其影响进入轨迹；事后审计者不属于被观察闭环。

## 4 三层共享的证据与分析视图

| 视图 | 最小证据单元 | 必须区分 |
| --- | --- | --- |
| R2 事件视图 | 动作、当轮输入、状态前后版本、执行结果 | 生成、执行尝试、实际生效；C/P/R 与 I/V/T |
| R3 关系视图 | 来源事件、消息读取、状态版本读取、后续动作 | 时间先后、可见性、实际引用、语义依赖、因果作用 |
| R4 闭环视图 | 多轮依赖链、反馈返回、版本继承与再次调用 | 通信回路、权限穿透闭环、自增强、普通纠错 |

Bias × Authority 的 3×3 事件矩阵、Bias × Bias 的转移矩阵、Authority 干预效果矩阵是不同统计对象。共现不能当作转移，先后不能当作因果。C/P/R 与 I/V/T 独立编码，不固定 R→T，也不把所有同一权限动作强行归为同一偏差。

R3 的边应注明证据类型。消息送达或字段可见只证明暴露机会；模型明确引用可支持依赖判断，因果作用还需对照。记录级引用由系统生成，语义依赖可以晚审并保留不确定性。

时间展开的事件依赖图通常向未来展开。R4 所谓闭环，是角色、字段、任务或决策状态在不同版本间形成反馈，不要求事件图出现逆时间的有向环。报告闭环时必须声明投影对象与版本对应关系。

每批证据固定任务、角色池、配置、模型、代码、原始文件及哈希。保存每轮可见输入、原始输出、解析动作、消息生命周期、调用执行、状态历史、剩余队列、终止原因、失败与用量。原始记录缺失时标为 NOT_RECORDED_IN_SOURCE_VERSION，不补写为同期事实。

## 5 自增强权限穿透闭环的观察原则

发现组允许重复调用、回溯、意见冲突、停滞和反馈持续出现。不得仅因疑似 C/P/R、重复或偏离就自动去重、纠偏、增加审计 Agent 或宣布任务结束。合法纠错也允许存在，闭环标签由证据决定。

候选闭环的核心是：未经授权获得系统效力的状态，被下游继承，其后续产物又成为继续修改状态、扩展调用或重新打开任务的依据。它可以涉及部分维度或同维持续，不要求严格的 C→P→R→C 顺序。

| 证据等级 | 可作出的表述 |
| --- | --- |
| 通信重复或回路 | 存在重复交互，尚不等于偏差闭环 |
| 越权状态被下游继承 | 存在传播候选链 |
| 后续产物再次支持同一过程 | 存在反馈闭环候选 |
| 反馈扩大影响范围或反复维持穿透 | 存在自增强迹象 |
| 切断指定依赖后增强减弱 | 为闭环机制提供干预支持 |

“黑洞”仅作现象描述。可测量对象包括反馈迭代次数、状态影响范围、调用图增长、重开深度、任务目标忠实度和来源识别能力。运行 Agent 可能失去来源辨别能力，实验记录仍应保存完整来源；日志缺失不能当作黑箱化证据。

预先固定轮次、时间、调用或 token 上限。外部上限触发时记录 BUDGET_CENSORED，并保留具体原因、待执行工作和最后状态；这既不是自然完成，也不能证明无限循环。到上限仍未观察到的事件属于观测窗口内未出现，不能直接推断永不发生。

### 5.1 基础层：固定窗口负责“测得准”

基础层不追求把系统跑到极限，而是在统一观察窗口内稳定测量：事件发生、Authority 路径、下游读取/继承、反馈候选以及参与拓扑。当前基础窗口为 32 turns；被截断轨迹按 censor-aware 规则解释。

基础层的统计语言必须明确为 fixed-horizon，例如“by turn 32 observed”，不得把窗口内未出现解释成 whole-episode zero。

在基础层的 subject transport、immutable evidence、客观统计、review packet 绑定与真实多 Agent 执行稳定以前，不进入上限 K 实验。

### 5.2 上限层：循环预算负责“看得远”

上限层不再用不断增加 turn limit 作为主要实验变量，而使用有限的循环预算 K。K 表示未来冻结定义下的 **neutral structural feedback round** 数量，不是 C/P/R 次数，也不是 Authority violation 次数。

Runtime 的 K 计数必须语义盲：不得读取 C/P/R、授权判断、Authority penetration、自增强标签或 evaluator 输出。结构循环计数器需先离线定义、版本化和测试，之后才能启用真实 K 条件。

初期 K 仅允许 2 和 4：

`BASE stable → K=2 → deferred review gate → optional K=4 → deferred review gate → STOP`

K=2 若没有至少一个 C/P/R 维度出现可复核的 persistence / expansion / amplification candidate，则停止上限实验，不支付 K=4。

K=4 只有在 K=2 gate 通过后才运行。K 增加后，不要求 C/P/R 三者同时增长；至少一个维度在 amplification-qualified metric 上增加即可进入“有上限增强信号”的候选解释。

### 5.3 “增加”不能只是累计事件变多

K=4 比 K=2 多两个循环机会，因此累计 C/P/R 数量机械增加不能单独证明增强。

初期合格指标包括：

- 每个 feedback round 的新增 reviewed Bias event；
- 受影响 Agent 的去重数量；
- 受影响状态字段的去重数量；
- reviewed propagation depth；
- reviewed re-inheritance / reopen depth。

K=4 轨迹的 rounds 1–2 与 3–4 可以作探索性 within-trajectory prefix 对比，以节约发现阶段成本；但它不等价于未来确认性研究中的独立 K=2 arm。

通过 K=2/K=4 只允许表述 persistence signal、expansion signal 或 amplification candidate。因果 self-reinforcement 仍需 R5 通过切断相关反馈依赖后观察增强减弱来支持。

## 6 对照实验与各层证据门槛

R2 的门槛是事件记录与机制判别可信，不再要求先得到对角占优才允许记录 R3/R4。R3 的描述性关系可以先审计，因果主张需要排除共同输入、调度和资源变化等解释。R4 只有观察到反馈不够，进一步的自增强主张需要重复证据及适当对照。

同一任务多次自由运行用于发现实际执行人数和拓扑变化。研究人数效应时随机改变可用角色池，并平衡专业覆盖；实际参与人数可能是偏差的结果，须保留偏差发生前的结构。信息量应拆分有效信息、冗余、冲突和碎片化；复杂度应区分约束、依赖和决策难度。预算梯度单独固定，避免同时改变多个因素却归因于一个因素。

上限 K 实验使用 sequential spending gate，而不是预先铺开多个高 K 条件。K=2 是第一个昂贵探针；仅在 K=2 产生至少一个 C/P/R 增强候选后才允许 K=4。任何 K>4 条件都要求新的 Change Note、独立成本复核和重复信号，不从 K=4 自动外推。

R5 使用单维、双维和 Full Authority 条件，实际阻断后继续运行，测量风险迁移、任务成功和误拦截。静态回放仅回答即时事件是否被拦截。R6 比较 Full Rerun、Checkpoint Retry 与 ALR；ALR 从有证据支持的最早越权祖先定位污染依赖闭包，保留无关成功节点，并记录恢复带来的新偏差。

所有 Gate 都是研究主张的证据门槛，不是主体采集许可。正式确认批次前冻结主要指标、排除规则、统计单位与比较方式；同一轨迹多个事件及同一证据多个评审不能当作独立主体样本。探索中修改假设应记录，并由新数据验证；结果不支持时缩小主张，不能删除有效反例。

## 7 仓库状态与迁移安排

当前 Arena v0.3.2 已完成 subject JSON transport 验证，并建立 immutable evidence、censor-aware objective stats、R2/R3/R4 structural views 与 deferred review 接口。Format Verify 005 在 32 turns 时仍有 pending work，因此 32-turn base 被明确解释为固定观察窗口，而不是自然上限。

历史电商 5 条轨迹保留。CN-R2-023 的复核记录显示，前四条激活 4 人但实际只有 1 人执行；第 5 条有 6 人执行。因此旧样本不能表述为五次完整的多 Agent 协作。旧评价仍是特定版本评审意见，多模型一致性、稳定频率、传播因果和自增强尚未由这批小样本确认。

| 状态 | 项目 |
| --- | --- |
| 已有基础 | 自由路由、证据优先/延后审计、客观参与人数区分、结构关系导出、censor-aware 统计 |
| 当前新增 | Base fixed-window 与 Upper-bound K 分层；K=2/K=4 sequential spending gate |
| 待落实与验证 | semantic-blind structural feedback round counter；K 条件运行/证据绑定；K gate review summary |
| 后续实际实验 | Base 稳定后 K=2；仅 gate 通过后 K=4；再之后才考虑 R5/R6 与跨领域/模型泛化 |

实施时沿用 Arena 和现有证据/评审接口，引用同一批次哈希。基础与上限条件分别绑定配置版本；不得把 32-turn fixed-window、K=2 与 K=4 静默混算为同一实验条件。

## 8 复现交付与论文安排

每份事件意见、关系意见和闭环意见均绑定 evidence_batch_hash、所引用事件/版本、reviewer、model/config、rubric/prompt version、时间、依据和不确定性。复核、比较与裁决追加保存；分析脚本明确选择哪份审计版本生成表格。

R8 从采集起执行增量冻结，最终固定 source commit、任务与模型配置、原始轨迹、审计层和图表源数据。主体失败、观测截断、待审和无偏差分别呈现。评审成本与主体成本分开核算，先复用已有证据，后按研究价值选择追加评审或新运行。

R9 按现象、机制、动力学、控制与恢复组织论证，不要求正文按 R 编号排列。图表应分别表达事件路径、传播证据、反馈迭代和干预结果。目标期刊沿用既有研究目标，投稿要求另行核对；本规划不作录用概率承诺。
