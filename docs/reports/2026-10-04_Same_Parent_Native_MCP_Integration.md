# Same-parent native MCP integration

The prior release separately demonstrated a terminal proposal and early host-only
continuation. The new integration joins inspected prefix evidence, concrete host
authorization, native MCP repair and scripted continuation on one early parent.

The parent is the frozen G3-X4-T2 sequence-4 capture, with 60 remaining decisions.
Its evidence window is verified by native history, passive action records and
exact MCP requests/responses: 5 checkpoints, 12 structural records and 9 native
MCP invocations. The planning graph contains 434 observations and 157 nodes;
later files, calls and terminal answers are inaccessible through source tools.

The scripted source proposal compiles one `run.py` field action. It traverses
the unchanged official MCP read/write/read tools, passes the existing controlled
route verifier and leaves host queue, inbox, history, task and budgets unchanged
before continuation. Four fixed responses then run through the unchanged host
loop, including one native MCP file read. Sequence advances 4 → 8 and remaining
budget 60 → 56. All 434 prefix observations and old graph edges are retained;
231 new observations produce a 665-observation / 396-node complete branch graph.

The clean frozen SDK/protocol sources and actual stdio initialization are checked.
No framework code or protocol is modified. Native action receipts, exact wire
bytes, recovery journal, after-repair/final checkpoints and independent-review
preparation are retained in 298 exactly reproducible artifacts.

Ten new boundary tests cover future evidence exclusion, complete available-source
access, membership mismatches, missing/rejected native responses, exact result
decoding, forged proposal/live provider rejection, missing runtime and one-use
host authorization. The route-repair suite now has 125 passing tests; the
enhanced-monitor suite has 12.

This is engineering evidence. The proposal and continuation remain scripted,
with no model call, natural rerun, actual repair agent exit or independent
semantic verdict. The archive lacks exact historical subject-provider prompts
and raw answers, so complete semantic lineage is not claimed. Historical launcher
use and semantic adoption remain unknown. Controlled handler checks do not
establish task completion or semantic repair. Review remains pending.
