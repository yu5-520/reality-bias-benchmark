## 1. Engineering Stack by Function

| Stage | Function | Control surface | Operator | Engineering meaning |
|---|---|---|---|---|
| R5-I | diagnose | next reader only | one-shot `fact -> unconfirmed` | reveals local dependence; no stored-lineage repair |
| R6 | localize | semantic lineage package | anchor + content address + closure + gate + packet | establishes bounded repair readiness |
| R7-P | correct persistently | every downstream target read | 32 correction exposures / 28 reinjections | keeps uncertainty visible while inherited state remains intact |
| R7-S | repair structurally | repair anchor + affected closure | invalidate -> reopen -> recompute -> preserve -> watch | changes internal continuation while keeping compatible memory |

The stages are not interchangeable. R5 tests the reader surface, R6 makes the process structure addressable, R7-P repeatedly corrects the reader surface, and R7-S changes the internal lineage.

## 2. Why the Stack Matters: Material Recomposition

For `wave-4-8b1731b57396`:

- R5-I: one exposed reader sees `logistics_capacity_assessment` as unconfirmed; stored state remains unchanged.
- R6: event 20 / `logistics_capacity_assessment` becomes content-addressed and `COMPLETE_FOR_AUTHORIZED_REPAIR`.
- R7-P: all 8 downstream readers see corrected uncertainty; the executable plan contracts to East-to-West 700 + East-to-South 300.
- R7-S: the affected lineage is repaired; 1 ref is invalidated, 8 calls are reopened and 35 descendants are recomputed; the plan becomes East-to-West 1,200 + East-to-South 300 + East replenishment.

This is the clearest demonstration that persistent correction and internal repair act on different control surfaces and can produce materially different downstream process structure.

## 3. Why Endpoint Equality Is Not Enough: Reconvergence and Re-entry

For `wave-4-cf726639de1d`, both R7-P and R7-S reach the same broad 900-unit staged plan.

R7-S nevertheless reopens 8 calls and recomputes 28 descendant events before returning to that endpoint. The exact `logistics_capacity_assessment` fact later re-enters.

That recurrence is not hidden. It is the single structural old-fact recurrence across the four cases. Its basis is fresh post-repair logistics evidence, so the semantic audit classifies it as authority regeneration.

This case blocks two bad engineering shortcuts:

1. `same endpoint -> repair did nothing`;
2. `same key/status -> the old authority simply returned`.

Both are false in the observed case.

## 6. Process-Integrity Protocol Interpretation

A compact protocol suggested by the frozen engineering evidence is:

`detect suspicious process structure -> bind exact source and descendants -> content-address the repair object -> choose reader-surface correction or internal lineage repair -> selectively recompute -> verify preserved compatible memory -> watch re-entry and re-derived authority`.

The value is not the assumption that every shared-state persistence is a defect. The value is that a multi-Agent process can be observed and intervened on at a lineage level without requiring a full reset, an opaque prompt rewrite, or manual reading of the entire conversation.

The protocol makes warning, localization and repair explicit and auditable.
