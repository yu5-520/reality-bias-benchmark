# 2. The Innovation Is a Stack, Not a Single Primitive

The sharpest contribution claim should not be reduced to whether any one component — provenance, rollback, memory, task boundary or fault attribution — has a prior-art neighbor.

Important components already do.

The stronger research object is the **end-to-end coupling of observation, semantic lineage, permission dynamics, content addressing and local repair around the same process object**.

## 2.1 One semantic object survives the whole lifecycle

The repository now carries formal interfaces that bind:

- `target_semantic_id`;
- `content_address`;
- `trace_root_ref`;
- source references;
- transformations;
- adoption relations;
- authority transitions;
- shared-pool states;
- dependent descendants;
- evidence-supported affected closure;
- repair closure;
- preserved unrelated references;
- old-lineage re-entry references.

This turns semantic meaning from a narrative explanation into an **addressable engineering object**.

A field/object-level semantic query can therefore be combined with content addressing and hash/evidence lineage to reconstruct the full relevant semantic line:

`source -> transformation -> adoption -> authority transition -> shared pool -> descendant decisions/actions -> repair closure`.

The point is not simply that each event is logged. The same semantic object can be **retrieved, reconstructed, audited and repaired** across stages.

## 2.2 Semantic Process Integrity Stack

The current stack can be summarized as:

`Semantic Object / Field`  
-> `Content Address`  
-> `Hash / Evidence Lineage`  
-> `Functional Semantic Lineage`  
-> `Authority History`  
-> `Affected Closure`  
-> `Dynamic CPR Audit`  
-> `Repair Anchor`  
-> `Semantic Repair Packet`  
-> `Selective Reopen / Recompute`  
-> `Preserve Unrelated Semantics`  
-> `Re-entry Watch`.

This is the primary system-level innovation target.

It is not a claim that every primitive is independently unprecedented.

It is a claim that the repository now binds them into a continuous **observation-to-control research stack** around one addressable process-reality object.

## 2.3 Repository objects

| Layer | Repository object | Scientific / engineering role |
| --- | --- | --- |
| Identity | `target_semantic_id + content_address` | bind one semantic object/revision across files and stages |
| Lineage | `semantic_lineage_closure` | source -> transformation -> adoption -> authority -> pool -> descendants |
| Completeness | `lineage_completeness_gate` | block repair when source / transformations / authority history / descendants are unresolved |
| Repair | `semantic_repair_packet` | invalidate / revise / selectively recompute only the evidence-supported affected closure |
| Preservation | `preserved_unrelated_refs` | make non-interference an explicit repair objective |
| Post-repair | `old_lineage_reentry_refs` / hash watch | detect exact old authority re-entry or closure expansion candidates |

## 2.4 The central engineering shift

The engineering contribution is not another rerun strategy.

It is a shift from:

`run-level recovery`

toward:

`lineage-level semantic repair`.

A repair can:

- downgrade authority;
- revise a source;
- invalidate a shared-pool representation;
- invalidate affected descendants;
- reopen dependent decisions;
- selectively recompute affected descendants;
- preserve compatible unrelated semantics;
- watch for old-lineage re-entry or regenerated authority.

The target is not to rerun a probabilistic process until a satisfactory trajectory appears.

The target is to identify **which semantic lineage is affected**, repair that lineage, and recompute only what depends on it.

# 3. From Multi-Agent Reliability to Inter-System Process Reality

Multi-Agent interaction should be presented as the first controlled laboratory, not the ultimate theoretical boundary.

The deeper object is the **protocol relationship between interacting systems**:

> What semantic meaning, epistemic status, authorization scope and historical context survive when one system's representation becomes another system's input?

Multi-Agent systems are experimentally useful because the communication graph, shared state, authority changes, finalization and reopen operations can all be frozen and inspected.

But the theoretical nodes do not need to remain Agents.

A semantic lineage can pass through:

`Human -> LLM -> RAG -> Database -> Workflow -> Service -> ERP/CRM -> Tool -> Agent`.

What matters is whether a representation is:

`consumed -> transformed -> authorized -> reused`

across a system boundary.

## 3.1 Generalized Dynamic CPR

| Dimension | Agent-level reading | System-level reading |
| --- | --- | --- |
| **C — information permission** | unconfirmed / transformed information becomes decision-effective | **what may be treated as real after crossing a system boundary?** |
| **P — collaboration / execution permission** | Agents generate new monitoring, ownership or execution obligations | **how far may one system's output authorize another system to act?** |
| **R — temporal permission** | reopen / recompute generates new C/P | **under what conditions may historical process reality act again?** |

This preserves the first-paper evidence while exposing a broader research direction.

C/P/R remain empirically established only within the frozen studied trajectories.

Their inter-system formulation is an **outlook-level abstraction**, not a completed universal generalization.

## 3.2 From data contracts toward semantic-authority contracts

Traditional interfaces primarily guarantee:

- type;
- schema;
- required fields;
- format.

Process Reality suggests a broader contract surface:

- value;
- source provenance;
- epistemic status;
- authority scope;
- validity window;
- permitted downstream use;
- lineage address;
- re-entry policy.

Data can transfer correctly while the conditions that justified its use fail to transfer equivalently.

A future **Semantic-Authority Interface Contract** might distinguish, for example:

`value = 1520`  
`source = model_estimation`  
`epistemic_status = preliminary`  
`authority_scope = planning_only`  
`downstream_execution = forbidden`  
`valid_until = ...`  
`lineage_address = ...`.

The broader hypothesis is:

> **Reality Bias may emerge when representations cross system boundaries while the semantic, epistemic, authorization, or temporal conditions that justified those representations are not preserved equivalently.**

## 3.3 Why multi-Agent remains the right first experimental scene

The first-paper setting remains scientifically useful because:

- the communication graph and shared state are observable and controllable;
- every turn, handoff, state write, finalization and reopen can be frozen and addressed;
- authority can be challenged locally without changing the whole environment;
- repair and recomputation can be compared on the same frozen lineage;
- the setting exposes system-to-system mechanisms at a resolution that enterprise end-to-end environments rarely permit.

Thus:

> **Multi-Agent systems are an experimentally tractable microcosm of interacting adaptive systems.**

# 4. The Reflexive Human-AI Case: P-Like Expansion Outside the Arena

The repository contains a separate supplementary methodological story:

`docs/supplementary/NML_Supplementary_Note_S1_perfection_like_planning_drift.md`.

During construction of the experiment itself, an evidence-first research workflow accumulated a sequence of locally reasonable reviewer and infrastructure extensions until reviewer robustness began to behave as a blocking dependency for the structural research programme.

The sequence can be summarized as:

`evidence-first / deferred review`  
-> semantic ambiguity  
-> independent reviewer  
-> reviewer disagreement  
-> redesigned reviewer contract  
-> different-family reviewer requirement  
-> new provider/model integration  
-> full runner  
-> checkpoint recovery  
-> thinking controls  
-> cache optimization  
-> reasoning-latency telemetry  
-> reviewer robustness becomes a blocking dependency  
-> R Plan v3.1 restores reviewer robustness to supplementary R9 scope.

Each local extension was defensible.

The cumulative dependency relation drifted.

## 4.1 Scientific boundary of the reflexive case

| Status | What the supplementary case supports |
| --- | --- |
| Directly inspectable | the repository chronology and dependency shift can be independently reconstructed from commits and files |
| Interpretive only | the P-like mapping and Human-AI mechanism analogy |
| Not established | formal CPR adjudication, prevalence, causality or generality in Human-AI systems |
| Future hypothesis | locally reasonable system-to-system authorizations can accumulate into global goal/scope divergence |

The significance is **not** that Supplementary Note S1 proves Human-AI P.

It does not.

Its scientific value is reflexive: a Human-AI workflow generated a structure consistent with the broader Process Reality hypothesis without being constructed as a Reality Bias experiment.

## 4.2 Cumulative local authorization drift

The interaction can be abstracted as:

`human goal`  
-> `AI proposes locally reasonable expansion`  
-> `human locally authorizes`  
-> `expanded state becomes inherited context`  
-> `next expansion is proposed from the new default`  
-> `cumulative scope may diverge from the original evidence-supported objective`.

This motivates the future proposition:

> **Local authorization does not necessarily imply global goal fidelity.**

The risk is not necessarily one obviously irrational decision.

A sequence of locally reasonable decisions can gradually construct a globally different process reality.

## 4.3 A system-to-system interpretation

Human-AI interaction can be viewed as two adaptive systems repeatedly reading, transforming and writing back each other's representations.

This makes the supplementary case a bridge from Agent-Agent experiments toward a wider question:

> Can cumulative local authorization drift arise whenever interacting systems inherit one another's scope expansions as new process reality?

This remains a research question.

# 6. Open Evidence Addressing and Replication Architecture

Open-sourcing the experimental repository changes external replication from a vague future collaboration into a prepared research interface.

The paper does not need to print every turn or lineage edge if:

1. the paper contains a sufficient scientific argument; and
2. every supporting object can be addressed back to frozen evidence.

## 6.1 Three evidence layers

| Layer | Purpose | Minimum content |
| --- | --- | --- |
| Paper | sufficient scientific argument | mechanism, representative complete paths, contrasts, aggregate boundaries |
| Supplement | extended evidence | additional cases, comparator routes, semantic transformation ledgers, censor details |
| Repository | complete traceability | raw frozen evidence, case IDs, manifests, artifact hashes, lineage records, validators, superseded history |

The repository is therefore not a substitute for the paper.

It is the **complete traceability layer**.

## 6.2 Addressability as part of the research method

A paper locator can point:

`claim`  
-> `case ID`  
-> `trajectory audit record`  
-> `source registry`  
-> `manifest`  
-> `artifact digest`  
-> `raw frozen evidence`.

This supports a crucial methodological statement:

> **The main retrospective mechanism synthesis is derived from frozen trajectories rather than trajectories regenerated until they fit the final theory.**

## 6.3 Two replication modes

### Offline reproducibility

An external reader can:

- verify hashes;
- rebuild deterministic derivations;
- inspect semantic packets;
- regenerate reports;
- inspect superseded historical states;

without calling a subject provider.

### Independent experimental replication

An external group can provide its own model/provider and execute a frozen replication contract under:

- exact replication;
- model/provider variation;
- topology variation;
- framework variation;
- memory architecture variation;
- domain variation.

Open-source reproducibility is not the same as completed independent replication.

The repository supplies the infrastructure and evidence discipline.

External laboratories supply new stochastic realizations and external-validity tests.

Execution provenance is a necessary substrate.

The additional target is observing **how meaning and operational permission change**.

## 7.4 Vibe Coding and repository process reality

A repository may remain white-box while the process that formed it becomes black-box.

A requirement can become:

`requirement`  
-> `inferred assumption`  
-> `field/interface`  
-> `module`  
-> `code artifact`  
-> `downstream dependency`.

Once materialized, an out-of-scope artifact can be inherited by the next coding Agent as:

> “the system already works this way.”

The open question is therefore not only whether generated code is correct, but whether the **semantic authorization history of the repository remains inspectable**.

> **Artifact transparency does not imply process transparency.**

## 7.5 Enterprise / production systems

The production frontier may be shifting from capability acquisition toward **process qualification**.

A system can be capable yet unsuitable for production if the organization cannot state:

- what evidence was consumed;
- what authority was inherited;
- why scope expanded;
- which descendants depend on a disputed semantic object;
- how to repair it locally;
- whether old authority can re-enter later.

Potential production standards therefore extend beyond model capability toward:

- provenance;
- semantic authority;
- drift;
- audit;
- repair;
- re-entry;
- acceptance;
- recovery.

## 7.6 External validation programme

The compute-heavy robustness agenda is retained as external validation rather than treated as missing first-paper evidence:

- cross-model;
- cross-provider;
- cross-topology;
- cross-memory architecture;
- MCP/tool-agent environments;
- Agent-count scaling;
- task-complexity scaling;
- independent reviewer agreement;
- independent laboratory replication.

# 8. Final Innovation Position

Multi-Agent systems may be only the laboratory form of a broader inter-system problem.

The contribution of this first paper is to make **process reality observable as a dynamic semantic object**, trace how authority and scope change along its lineage, and carry that same addressable object forward into localized repair and selective recomputation.

The paper is therefore strongest when it does not compete for isolated primitive ownership.

Its sharper claim is architectural and directional:

> **Process Reality can be studied as a system-to-system integrity problem, and the repository demonstrates an end-to-end observation-to-repair stack for one experimentally tractable realization of that problem.**

A compact system-level formulation is:

> **Reality Bias concerns the loss, transformation, or amplification of semantic and operational conditions when process reality crosses system boundaries.**

And the corresponding engineering direction is:

> **From rerunning probabilistic systems to repairing addressable semantic lineages.**
