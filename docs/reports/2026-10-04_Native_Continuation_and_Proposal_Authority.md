# Early native host restoration and post-proposal exact authorization

The earlier native repair fixture used a terminal parent and separately
preselected write policies. Two new modules now verify a nonterminal native
host parent and derive exact execution constraints from an inspected proposal
inside a task capability envelope frozen before diagnosis.

## Results

- All 38 distinct G3-X4-T2 host checkpoints were verified against their content
  addresses, native state, context and application files.
- The existing first-eligible annotation is backed by the sequence-4 native
  capture. Its host queue, inbox, history, stop state, task and budgets restored
  exactly through the unchanged native host checkpoint adapter.
- The unchanged host continuation loop consumed four fixed scripted responses:
  sequence 4 → 8, remaining horizon 60 → 56. It retained the original history
  prefix and finalized through the host's actual specialist/entry-agent routing.
- The finalized terminal parent was refused even though 28 decisions remain.
- The passive monitor retained 110 source observations and full branch graphs.
- The prior manual terminal proposal compiled one application field action and
  one current-answer field. The capability envelope prescribed no exact field
  or replacement value. Rehashed value/dependency changes are rejected by the
  separately retained authorization before dispatch.
- Seventeen new boundary tests bring the route-repair suite to 115 passing tests;
  the enhanced-monitor suite remains 12 passing tests.
- All 126 new sealed artifacts reproduce exactly in a fresh directory. Existing
  system and independent-review evidence remain frozen and reproducible.

## Limits

These are two separate offline engineering checks, not a same-parent closed-loop
repair experiment. The original terminal proposal remains explicitly manual;
the archive check performs no additional native repair. Native dispatch is
exercised on synthetic fixtures. The early branch uses fixed scripted responses,
local `HostCheckout` and the original experiment-owned host resume loop, without
an attached foreign MCP runtime or a subject provider/model call.

An existing structural eligible annotation is not proof of the earliest semantic
fault. The terminal trajectory graph is not supplied to the early continuation.
Prefix-safe complete planning context has not yet been implemented. No actual
repair agent exit is fabricated, no independent reviewer is invoked, no frozen
natural experiment is rerun and no repair-success claim or branch promotion is
made. Failures retain state for read-only review and never authorize replay.

The next integration must join prefix-safe agent planning, native framework
bindings, repair execution/exit and subject continuation on one verified parent,
then apply an independently bound semantic review under the unchanged CPR rules.
