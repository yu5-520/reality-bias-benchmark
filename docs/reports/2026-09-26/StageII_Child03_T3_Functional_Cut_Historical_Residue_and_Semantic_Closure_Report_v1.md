# 1. Research Object: What Does “Retired” Mean?

T3 is deliberately designed around a common software-engineering ambiguity.

An old path can be:

1. **functionally disconnected** — it no longer controls runtime;
2. **structurally retained** — its file, module, manifest entry, note, or other artifact still exists;
3. **semantically active** — later agents still read, cite, reinterpret, or elevate it;
4. **process-active** — it still opens review, repair, release, or verification work;
5. **fully closed** — repository state, semantic account, and process termination agree.

These states are not interchangeable.

For this report:

| Term | Operational meaning |
|---|---|
| functional cut | the old path no longer governs current runtime behavior |
| structural residue | an old file/module/reference remains present after functional cut |
| state re-entry | previously deactivated or acknowledged historical material becomes process-relevant again in later observation/review |
| semantic closure | the system's terminal account accurately matches the persisted repository state |
| process closure | the execution actually reaches a terminal finalization state rather than only repeated handback or turn-budget stop |

The primary question is therefore:

> **After functional authority is removed, can historical structure still constrain later process?**

A terminal functional state is an endpoint measurement; it is not a substitute for the process lineage that produced it.

Observed process difference is not, by itself, evidence of inferior system quality.
