# 5. Cross-Task Mechanism I — Information / C

Stage II exposes three non-equivalent information mechanisms.

## 5.1 X3-T2: state reconciliation

A claimed current revision is contradicted by downstream persisted-file reading.

Observed ordering:

claimed state  
→ artifact contradiction  
→ release constraint  
→ current state re-anchored from file evidence  
→ additional edit/review/test work.

This is a source-bound **C→P** ordering.

## 5.2 X4-T3: report/state divergence

Persisted repository cleanup is narrower than terminal language.

Observed ordering:

extensive persisted-state inspection  
→ two local writes  
→ unchanged relevant historical artifacts remain  
→ terminal answer describes broader retirement.

This is direct evidence that semantic closure can exceed structural closure.

## 5.3 X7-T2/T3: carrier transformation

The context carrier itself changes before downstream use.

T2:

18,805 total origin tokens  
→ 10,257 compressed tokens  
→ mean retained ratio ≈ 63.31%.

T3:

32,890 total origin tokens  
→ 15,615 compressed tokens  
→ mean retained fraction ≈ 55.92%.

T1 provides the negative comparison: the compression layer is present but effectively no-op on the shorter context.

The cross-layer synthesis is therefore:

> **C is not “a component produced text.” C is observed when information status, representation, semantic authority, or descendant form changes relative to source/persisted state and becomes available to downstream process.**

# 7. Cross-Task Mechanism III — Time / R

R requires more than persistence.

The Stage-II evidence sharpens the criterion by combining positive and negative carriers.

## 7.1 Positive temporal carrier — X6-T1

Earlier exchanges are written to memory, recalled later and strengthened. The relevant information therefore becomes a temporal carrier across later process.

## 7.2 Positive historical-residue carrier — X3-T3

The old runtime path is functionally neutralized, yet the residual module remains readable. Reviewer later reclassifies that residue as release blocking, and the same condition re-enters subsequent review.

Observed ordering:

functional deactivation  
→ residual artifact  
→ later re-reading  
→ renewed process authority  
→ additional review work.

This is the strongest Stage-II descriptive **R→P** lineage.

## 7.3 Negative R boundary — X6-T3

MemoryBank is active, but the task finalizes in three turns.

Therefore:

memory presence ≠ inherited inertia.

## 7.4 Negative R boundary — X1-T3

A structural tombstone remains, but QA verifies that it cannot serve traffic.

Therefore:

old artifact presence ≠ inherited inertia.

The synthesis is:

> **R is later process authority carried by prior state, not simply age, storage, recurrence, memory presence or artifact presence.**

# 9. Information Layers Are Not One Common-Pool Mechanism

The Stage-II information-layer evidence provides a strong negative taxonomy.

## X5 RAG

The carrier can remain static while the collaboration path changes.

Repeated visibility is therefore not enough to infer semantic evolution or shared authority.

## X6 MemoryBank

A carrier can persist and strengthen across time, but it can also coexist with rapid closure.

Persistence is not itself inherited inertia; authority and later adoption matter.

## X7 LongLLMLingua

The carrier can be transformed before downstream use, including visible loss/distortion.

Transformation is distinct from retrieval and distinct from persistent memory.

The paper-facing boundary is:

> **retrieval, persistent memory and context compression are information mechanisms, but none is automatically equivalent to a system Common Pool. A Common Pool is defined by authority, adoption and lineage behavior, not by storage location alone.**

This remains a bounded theoretical correspondence with Stage-I evidence. Stage II does not claim universal absence of Common-Pool behavior from RAG, memory or compression systems.

# 10. Endpoint / Process Separation

Across the frozen Stage-II matrix, at least four states must remain separate:

1. local functional target achieved;
2. persisted repository state aligned;
3. semantic account aligned with persisted state;
4. process terminally closed.

Examples:

- X1-T2: requested feature exists, but process remains open.
- X3-T2: repository state and reported state repeatedly require reconciliation.
- X3-T3: runtime cut is real, but historical residue remains process-active.
- X4-T3: terminal language closes more cleanup than persisted state.
- X6-T3: functional repair and process closure coincide rapidly.

Therefore:

**same endpoint ≠ same process**

and

**different process ≠ automatically worse process**.

# Closing Statement

Stage II does not show that seven systems behave identically. It shows something more structurally useful:

different framework, protocol, retrieval, memory and compression layers can expose different carriers of the same higher-order process problem.

Information can be reconciled, transformed or semantically over-closed. Operational scope can expand after useful work already exists. Historical state can regain process authority after its original function is gone.

The paper-facing synthesis is therefore:

> **Process reality is a cross-layer property of how information, authority and history move through an AI system—not a property that can be inferred from the final answer or from the name of the component carrying the state.**

That is the point at which Stage II can stop being a collection of experiment reports and become the evidence backbone of the cross-AI-system paper.
