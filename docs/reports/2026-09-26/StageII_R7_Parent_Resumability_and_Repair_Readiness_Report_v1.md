Date: 2026-09-26

## 1. Question

The Stage-II monitor has already converted 21 frozen natural first attempts into 24 monitor-derived structural pressure/support episodes without semantic-audit input.

Before any repair continuation is allowed, this report asks a narrower engineering question:

> Can a repair branch start from the required frozen native parent without rerunning the stochastic prefix, modifying the studied framework, inventing missing state, or crossing an external information-system boundary?

This is a repair-readiness question. It is not a CPR interpretation and it is not a repair-efficacy result.

## 2. Frozen boundary

The audit used the 24 frozen monitor-derived packages, 21 frozen first-attempt archives, raw native/observer evidence, and frozen application fixtures/source hashes.

It used **0 natural reruns, 0 provider calls, 0 evaluator calls, 0 stochastic prefix replays, and 0 semantic-audit inputs**. No private framework runtime state was mutated.

## 3. Parent-resumability ladder

A same-parent repair branch requires progressively stronger evidence:

L0 prefix bound  
→ L1 application state bound  
→ L2 exact next-step model-visible context bound  
→ L3 native scheduler / queue / session state bound  
→ L4 public/native resume verified.

Only L4 authorizes active repair. This prevents a weaker reconstruction from being silently treated as the same native parent.

## 4. X1: application state is reconstructable, native parent is not

Five X1 monitor packages were audited.

For all five, the frozen AutoGen native event stream contains machine-readable write-file arguments. Those writes can be replayed deterministically against the frozen checkout fixture.

As a consistency check, replaying the complete frozen write sequence reproduces the frozen final checkout hash exactly for every X1 natural path represented by these packages.

Therefore the application checkout state at each selected X1 prefix is machine reconstructable and content-addressable. This does **not** establish a resumable AutoGen team/session parent.

The archive did not freeze a public/native serialized team state at the selected prefix. Exact next-step team state, speaker/scheduler state and full framework continuation state are therefore not proven restorable without reconstructive assumptions.

Result: **5/5 X1 packages remain PARENT_RECONSTRUCTION_BLOCKED, despite verified L1 application state.**

This distinction is important: the package can know *what the application state was* without knowing *how to resume the identical native multi-agent process from that point*.

## 5. X2: message evidence is insufficient for a native MetaGPT parent

The MetaGPT observer preserves environment/role-memory message copies, but the current frozen archives do not bind all prefix-local action effects, role state and environment scheduling/queue state into a public restorable snapshot.

The audit therefore does not infer missing state from later repository contents or from semantic interpretation.

Result: **all X2 repair packages remain PARENT_RECONSTRUCTION_BLOCKED.**

## 6. X3: A2A wire history is not the same as role-session restoration

The A2A condition preserves the protocol wire and role-call payloads. This gives strong protocol evidence, including sender/target, remaining-turn budget and the exchanged payload.

However, each role service also accumulated local tool observations/session state during execution. Those internal states were not frozen as public restorable parent snapshots.

Directly writing those private session dictionaries would violate the Stage-II repair boundary.

Result: **all X3 repair packages remain PARENT_RECONSTRUCTION_BLOCKED.**

## 7. X5 / X6 / X7: observable carrier is not a writable repair surface

Seven packages originate from immutable external information-carrier conditions: RAG retrieval, MemoryBank recall/state, and LongLLMLingua context transformation.

The repair protocol forbids modifying those systems internally.

The audit therefore searched only the structural prefix at or before each frozen repair point for a machine-bound downstream application/message object that could legally receive a native repair.

None of the seven frozen prefixes contains a sufficiently bound legal downstream repair surface without semantic inference or future-suffix use.

Result: **7/7 remain LINEAGE_GAP_BLOCKED.**

This is not permission to repair the RAG index, memory store or compressor. The blocked result preserves the original system boundary.

## 9. Interpretation

The result exposes a real engineering distinction between **observability** and **recoverability**.

The Stage-II observer retained enough evidence to find pressure/support structure across heterogeneous systems. That does not automatically mean the same evidence is sufficient to restart an arbitrary historical native process state.

In particular:

process observability  
≠ application-state reconstructability  
≠ framework-native resumability.

X1 demonstrates the middle category directly: the checkout state can be reconstructed and independently verified while the identical AutoGen team parent cannot yet be restored under the frozen rules.

## 10. What the experiment must not do next

The repair experiment must not solve this readiness gap by rerunning the natural prefix until a similar state appears, replaying subject/model decisions to manufacture a parent, constructing private framework state by hand, adding a new privileged framework API, bypassing A2A or MCP, rewriting RAG/MemoryBank/LongLLMLingua internal information state, or using the completed semantic audit to fill missing structural state.

Each of those would change the scientific object or the already-frozen experimental geometry.

## 11. Handoff

Active repair remains closed.
