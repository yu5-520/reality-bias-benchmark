# Monitoring and attached repair system: offline closure implementation

## Result

The active offline coordinator now connects an inspected proposal to native branch execution, trusted verification, full observation capture, a continuation assessment and interruption reconciliation. A successful native write is no longer a system-level repair completion. The final state remains `AWAITING_NATIVE_CONTINUATION` until a real repair-agent exit, native continuation and independent semantic/authority evaluation exist.

This implementation uses one already sealed manual G3-X4-T2 proposal, not a newly generated agent plan. It performs no new model call, no natural-subject rerun, no semantic re-adjudication, no branch promotion and no private product import. Previous frozen monitor, audit, trial and integration evidence remains unchanged. The new evidence is an engineering-only dataset.

## Implemented behavior

| Requirement | Implementation | Remaining boundary |
| --- | --- | --- |
| Safety | Re-read successful native-source queries, reconstruct witnesses, recompile the complete proposal against separately retained policies, check native versions/dependencies and verifier-induced application drift | Sequential copied-branch checks; no concurrent native isolation |
| Effectiveness | Record obligations for old C/P authority, historical re-entry, transformed descendants and unrelated semantic progression; refuse to infer repair success from writes, file retention or endpoint correctness | Independent semantic evaluator and continued subject operation pending |
| Automation | Automatic offline execution/verification/capture/pending gate from an inspected manual/scripted bundle | Agent diagnosis and plan generation pending |
| Reuse | Common public contract and separate host-supplied native/verification bindings; multiple-object fixture and one MCP application/current-answer integration | Seven-system repair reuse not established |
| Traceability and recovery | Durable host-owned hash-chained intent/result journal and read-only current-version reconciliation | No automatic write replay, rollback or native checkpoint restoration |

The original broad coding task is preserved. Task/capability boundaries precede diagnosis; exact grants and values are fixed after a proposal and before native actions. The integration's policies remain explicitly manual. This does not demonstrate that an agent can independently select a repair location or write scope.

## Actual engineering route

Frozen complete MCP graph and source catalog → host query replay and witness reconstruction → complete proposal recompilation → one `run.py` conditional default change through `HostCheckout.write_file` → trusted controlled-route verification → current host `/answer` supersession through `SoftwareHostCheckpointAdapter.load_state` → full graph freeze → source-bound continuation assessment → recovery reconciliation.

The manual proposal has two source-based claims: the conditional alternate launcher and captured frontend changes versus the terminal account. Original historical launcher use and downstream adoption of the account remain unknown. The documented direct current-service route already worked. The host verifier checks current responses, explicit legacy mode and the alternate default selection on two methods and one cart; it does not test a browser or real payment processing.

## Validation

Nineteen new adversarial/behavioral tests pass. They cover fabricated re-sealed citations, missing native verification capabilities, verification failure after partial writes, unrelated verifier mutations, source-version drift, an attempted repeated execution, old C/P/re-entry obligations, literal version appearance in a new carrier, cross-clock ambiguity, false exit records, altered raw captures, rewritten historical records, interruption before/after a write, failed native output, journal drift, stale coordinators and multiple versions of one object.

The route suite has 86 passing tests; the enhanced-monitor suite has 12 passing tests. Fresh-directory reproduction compares all 67 sealed artifacts exactly. The existing workflow also independently reproduces historical branch and proposal fixtures before this new system integration; its new step runs `scripts/check_stage2_monitor_repair_system.py --compare-frozen` without provider credentials.

## Next implementation boundary

The system foundation now prevents a mechanical completion from being reported as a semantic repair. Implement agent-generated evidence-grounded diagnosis/planning, independently bound semantic assessment, monitored native continuation and actual native recovery; freeze same-parent methods/budgets/outcomes after those capabilities have receipts. Current live execution remains disabled. No historical subject is rerun to replace an earlier result.
