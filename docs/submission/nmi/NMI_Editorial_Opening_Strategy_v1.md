# NMI Editorial Opening Strategy v1 — From an Unchanged Value to a Changed Reality Permission

Date: 2026-09-20  
Status: **CANONICAL OPENING STRATEGY / SUBMISSION NARRATIVE ONLY / NO EVIDENCE MUTATION**

## 1. Editorial objective

The first page must make an editor understand the paper before encountering:

- R2-R9 chronology;
- the full CPR vocabulary;
- repository engineering;
- 150-trajectory accounting.

The opening must create one immediate scientific question:

> **How can an unchanged piece of information acquire a different permission to count as reality?**

The opening therefore begins with one natural trajectory and one theory.

---

# 2. Canonical opening case

Primary opening case:

`ec-discovery::formal_batch001::2::arena-ecommerce-0002`

Scientific status:

- natural E-commerce discovery trajectory;
- not generated by a later intervention;
- Dynamic C = high-confidence supported anchor under R8;
- frozen before the final R8/R9 synthesis.

## 2.1 Minimal case story

The system is constructing a seven-day operating plan.

The source contains:

`A stock ~1,520`

with the explicit status:

`preliminary / unreconciled`.

Later Agents perform:

- arithmetic;
- headroom checks;
- risk interpretation;
- plan construction.

But no new independent warehouse reconciliation appears.

Nevertheless, the same inventory object later becomes:

`fact / reconciled_by_inventory`

and the final plan consumes that stabilized inventory reality.

Minimal trajectory:

`1,520 preliminary/unreconciled`
-> `provisional inventory assessment`
-> `specialist arithmetic / headroom validation`
-> **no new independent warehouse reconciliation**
-> `1,520 fact / reconciled`
-> `final plan consumes it as operational reality`.

## 2.2 The crucial novelty surface

The opening must not imply that the central defect is a changed number.

The value can remain:

`1,520 -> 1,520`.

What changes is the permission attached to the value:

`preliminary -> fact`

`unreconciled -> reconciled`

`risk signal -> operational premise`.

Canonical hook sentence:

> **The value remained unchanged. Its permission to count as reality did not.**

This is the shortest route to the paper's object.

---

# 3. First theory: Process Reality

Do not introduce Dynamic C/P/R before the reader understands the case.

The first theoretical object is:

> **Process Reality**

Working definition:

> **Process Reality is the evolving set of representations that an interacting AI system is permitted to treat as real, actionable or still operative during execution.**

The theory is deliberately broader than correctness of a single value.

The opening contrast is:

`source-justified reality`

versus

`system-constructed process reality`.

In the opening case:

Source-justified state:

`1,520 / preliminary / unreconciled`.

Later system-constructed state:

`1,520 / fact / reconciled / decision-effective`.

The scientific question is therefore not only:

> Is 1,520 true?

It is:

> **What changed the system's permission to use 1,520 as a reconciled fact?**

---

# 4. First mechanism: Semantic Authority Migration

Only after Process Reality is intuitive should the paper name the first mechanism.

Working definition:

> **Semantic Authority Migration occurs when a representation acquires greater operational or epistemic permission through transformation, inheritance or reuse without a commensurate increase in independent evidential support.**

Opening-case signature:

`independent support remains materially flat`

while

`semantic / operational authority increases`.

This mechanism should be introduced before the letter `C`.

The intended cognitive order is:

`natural case`
-> `Process Reality`
-> `Semantic Authority Migration`
-> `Dynamic C`
-> `Dynamic C/P/R`.

The paper must not ask the editor to decode a taxonomy before seeing the phenomenon.

---

# 5. Why this case opens the paper better than P or R

## P as first case

The software-engineering P case is intuitive:

`one executable release decision`
-> continued monitoring / verification / ownership obligations.

But as an opening it risks being read as:

- over-planning;
- verbosity;
- unnecessary tool use;
- ordinary scope creep.

It remains a strong second mechanism.

## R as first case

The R examples are theoretically rich but require the reader to understand:

- closure;
- reopen;
- temporal boundary;
- historical permission;
- regenerated downstream C/P.

That is too much cognitive load for the first page.

## R7 repair as first case

Repair is strongest after the reader already believes the target phenomenon exists.

Therefore the preferred narrative function is:

- **C opens the door;**
- **P and R establish that the phenomenon is broader and dynamic;**
- **Functional Semantic Lineage explains continuity;**
- **R5/R6 exposes mechanism;**
- **R7 closes the loop with control.**

---

# 6. First-page cognitive sequence

The first page should produce three progressively deeper realizations.

## Realization 1 — a natural anomaly

A preliminary estimate becomes a reconciled fact without new independent reconciliation.

## Realization 2 — the object is not value correctness

The number remains unchanged.

What changes is the system's permission to treat it as reality.

## Realization 3 — a new system layer is required

The relevant research object is the evolving process reality constructed during interaction.

Suggested prose sequence:

> Multi-agent AI systems are usually evaluated by what they finally answer or do. Yet the same output can be reached through internal states that grant very different authority to the information they contain. In one natural trajectory, an inventory estimate of approximately 1,520 units entered the process explicitly marked as preliminary and unreconciled. Subsequent agents performed calculations and planning around it, but no new warehouse reconciliation was introduced. The same inventory object nevertheless later appeared as a reconciled fact and was consumed by the final plan. **The value remained unchanged. Its permission to count as reality did not.**

Then:

> **We call this evolving layer Process Reality.**

Only after this point should the manuscript introduce Semantic Authority Migration and later Dynamic CPR.

# 7. Opening theory ladder

Canonical order:

1. **Natural case** — unchanged value, changed reality permission;
2. **Process Reality** — what the system is allowed to treat as real/actionable/still operative;
3. **Semantic Authority Migration** — first mechanism;
4. **Dynamic C** — information-permission dimension;
5. **Dynamic C/P/R** — generalized permission dynamics;
6. **Functional Semantic Lineage** — how influence survives carrier transformation;
7. **Local authority perturbation / System Inertia** — mechanism exposure;
8. **Lineage-addressed repair** — control;
9. **Inter-System Process Reality** — Discussion / outlook only.

This ordering is mandatory for Manuscript v0.1 unless a later editorial attack round identifies a specific failure.

---

# 8. Claim guard

The opening case supports:

- a natural authority transition;
- lack of new independent warehouse reconciliation in the reviewed trajectory;
- downstream operational consumption;
- high-confidence Dynamic C under R8.

It does not support:

- universal prevalence;
- deliberate deception;
- proof that 1,520 was factually false;
- proof that every arithmetic transformation is bias;
- universal causal attribution to a single Agent;
- system-level generalization beyond the studied realization.

The novelty is not:

> “the model produced a wrong number.”

The novelty target is:

> **the system changed the epistemic and operational permission of an existing representation while independent evidential support remained materially flat.**
