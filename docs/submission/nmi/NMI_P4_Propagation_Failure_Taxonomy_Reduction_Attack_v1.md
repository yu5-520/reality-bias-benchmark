# NMI-P4 Reviewer Attack 04 — Propagation and Failure-Taxonomy Reduction

Date: 2026-09-20  
Status: **REDUCTION ATTACK HARDENED / NO NEW SEMANTIC ADJUDICATION**

## Attack question

> Is Process Reality merely ordinary information propagation, persistence, reopening or an existing multi-agent failure taxonomy with new terminology?

This attack tests whether the proposed object has any operational content beyond already familiar observations that information travels, agents collaborate, memory reappears or systems fail.

The correct defence is not a novelty slogan. It is a reduction test:

> If Process Reality is reducible to propagation, collaboration, persistence or reopening, then those structural/process events should be sufficient for the corresponding C/P/R verdict.

The frozen evidence does not support that sufficiency.

## 1. Reduction test: propagation -> Dynamic C

Ordinary propagation asks whether information remains visible or influential downstream.

Dynamic C asks a stricter question:

> Did the semantic lineage acquire greater epistemic or operational permission than its independent evidential support justified?

The study already contains a direct negative comparator.

Across the nine reviewed e-commerce discovery-history trajectories:

- functional semantic continuation is observed in **9/9**;
- continuation is explicitly broader than Dynamic C;
- only a subset of those continuations receive a C verdict.

Therefore:

`semantic continuation != Dynamic C`.

Healthy continuation can preserve:

- uncertainty;
- provisional status;
- conditional action;
- provenance;
- a need for later verification.

A C finding requires a permission transition, not mere downstream influence.

## 2. Reduction test: collaboration/activity -> Dynamic P

A structural collaboration metric can count:

- number of Agents;
- number of invocations;
- number of messages;
- amount of post-result work.

None is sufficient for Dynamic P.

The canonical P comparison is:

`original_goal <-> authorized_boundary <-> realized_process_scope <-> final_result`.

P is supported only when the realized collaboration/execution scope extends beyond what the goal required or separately authorized.

This yields two important counterexamples to a simple activity reduction:

1. **more collaboration can be healthy** when specialist decomposition is necessary to the original task;
2. **P can occur without a new Agent** when already-active Agents generate additional monitoring, verification, ownership or execution obligations.

The structural-scout attack empirically exposed the second point: a narrow P proxy based on first activation of a new Agent captured only 4 of 13 later P-supported trajectories.

Therefore:

`more Agents / more calls / more messages != Dynamic P`.

## 3. Reduction test: reopening/memory -> Dynamic R

Dynamic R is not:

- memory retrieval;
- state recurrence;
- reopening;
- recomputation;
- rollback by itself.

R requires a retrospective operation to reactivate prior process reality in a way that **generates a new C or P event**.

The protocol therefore permits:

`reopen / recompute -> no generated C/P -> R NOT_ESTABLISHED`.

Thus:

`retrieval or reopen != Dynamic R`.

This distinction is especially important for long-running systems, where healthy recomputation is normal.

## 4. Reduction test: persistence -> System Inertia

If all persistence were treated as pathology, the theory would collapse into a relabelling of shared-state memory.

The canonical R5 set provides a stronger negative comparator:

- canonical cases: **29**;
- cases better explained by normal inheritance, uncertainty-preserving continuation, independent re-anchoring or pre-existing conservative gates: **25/29**;
- stronger case-level structures consistent with System Inertia: **4/29**.

Therefore:

`persistence != System Inertia`.

The framework preserves the fact that a shared system is supposed to remember useful information.

## 5. Failure-taxonomy reduction

A failure taxonomy classifies observed failure forms or outcomes.

Process Reality is used here as a mechanism-level object linking:

`semantic formation`
-> `authority/scope/temporal permission`
-> `functional lineage`
-> `bounded perturbation`
-> `affected closure`
-> `localized repair`
-> `re-entry watch`.

This does not make failure-taxonomy work irrelevant, nor does the paper claim that every component is individually unprecedented.

The narrower distinction is that the study does not require a terminally wrong answer to define its object.

The same endpoint may coexist with different internal process realities, and repair can change the evidential/semantic lineage while the broad endpoint reconverges.

Therefore Process Reality is not presented as:

> “a new list of MAS failure categories.”

It is presented as:

> **an execution-level integrity variable describing what representations, scopes and historical states are permitted to remain operational, and how those permissions can be traced and repaired.**

A future taxonomy could certainly include Process Reality failure phenotypes. That would not reduce the mechanism to the taxonomy any more than naming an outcome category replaces the process that produces it.

## 6. Falsification boundary

This attack also clarifies what evidence would weaken the distinction.

The framework would be poorly differentiated if future replication showed that:

- every semantic continuation was always labelled C;
- P could be predicted solely from Agent/message/call counts;
- every reopen/retrieval was automatically labelled R;
- every persistent descendant was automatically labelled System Inertia;
- semantic repair reduced to whole-run rerolling with no lineage-specific intervention.

The current protocol and frozen evidence explicitly allow and observe the opposite cases.

## 7. Manuscript consequence

The paper may make three concise non-equivalences explicit:

> **propagation != authority migration**

> **collaboration/activity != scope-permission expansion**

> **retrieval/reopen != retrospective-generative permission**

and one persistence guard:

> **persistence != System Inertia**

These are operational distinctions tied to verdict criteria and healthy counterexamples, not merely terminological definitions.

## Verdict

Attack:

**“This is ordinary propagation / another MAS failure taxonomy.”**

Verdict:

**NOT SUPPORTED AS A COMPLETE REDUCTION.**

Reason:

The broader structural/process phenomena are necessary observation surfaces but are not sufficient for C/P/R or System Inertia. The frozen evidence contains healthy and non-positive cases that preserve propagation, collaboration, reopening or persistence without promoting them to Process Reality violations.

Claim boundary:

> This result differentiates the operational object used in the paper; it does not establish a universal first-ever novelty claim against all prior reliability taxonomies.
