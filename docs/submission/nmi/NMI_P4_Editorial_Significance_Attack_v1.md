# NMI-P4 Editorial Attack 09 — Breadth and Editorial Significance

Date: 2026-09-21  
Status: **EDITORIAL POSITION HARDENED / NO ACCEPTANCE PREDICTION**

## Attack question

> Why should this be read as a Nature Machine Intelligence Article rather than a narrow multi-agent engineering paper?

This is not a question that can be “proven” by repository evidence. It is an editorial-positioning test against the journal's stated scope and editorial criteria.

The current Nature Machine Intelligence editorial guidance states that first editorial decisions consider the degree to which a manuscript advances understanding, the soundness of conclusions, whether the evidence supports those conclusions, and the wide relevance of the conclusions to the journal's readership. The journal's stated scope explicitly includes multi-agent systems.

The correct task is therefore to show how the paper addresses these dimensions without inflating its claims.

## 1. Advance in understanding

The paper's strongest conceptual move is not a larger benchmark.

It separates:

`output correctness`

from:

`process reality`.

The opening case demonstrates why this distinction can matter:

- the value remains unchanged;
- evidential status changes;
- operational permission changes;
- downstream action becomes justified by a different internal reality state.

The paper then turns that observation into a mechanism programme:

`Process Reality`
-> `Dynamic C/P/R`
-> `Functional Semantic Lineage`
-> `local authority perturbation`
-> `persistence / ancestry analysis`
-> `lineage-addressed repair`.

The advance claim is therefore:

> **reliability can require qualification of the process by which representations become real, actionable or operative, not only evaluation of the final answer.**

That is broader than one e-commerce planning failure and narrower than a universal theory of AI reliability.

## 2. Soundness of conclusions

P4 intentionally reduced several stronger claims.

The manuscript now explicitly rejects:

- pooled prevalence from the heterogeneous 150-trajectory inventory;
- preregistered semantic-confirmation language;
- unique R5 causality;
- universal R7-S superiority;
- endpoint inequality as the sole repair metric;
- cross-domain evidence as cross-model or cross-system validation;
- universal Inter-System Process Reality;
- production validation of Monitor/Repair governance.

This restraint is not an editorial weakness.

It makes the central supported claim easier to audit:

> a process-level permission mechanism can be observed, traced, locally challenged and selectively repaired in the studied interacting-AI runtime.

## 3. Evidence architecture

The evidence is stronger as a linked mechanism chain than as any one sample-size headline.

The paper combines:

- a natural high-clarity exemplar;
- held-out domain variation;
- complete-trajectory semantic reconstruction;
- negative/healthy comparators;
- local one-shot perturbation with bounded causal language;
- passive semantic ancestry analysis;
- content-addressed lineage repair;
- preservation and re-entry watch;
- explicit attack-calibrated limitations.

This supports a mechanism paper.

It does not support a population survey.

## 4. Wide relevance without universal generalization

The relevance argument should not be:

> “the same rate has been proven across all AI systems.”

It should be:

> interacting AI systems increasingly share, transform, persist and reactivate intermediate state; endpoint metrics alone may therefore miss changes in what the system is permitted to treat as real or actionable.

The held-out Finance, Supply Chain and Software Engineering domains show that the experimental object is not tied to the original e-commerce semantics.

At the same time:

- cross-model robustness is not established;
- cross-system generality remains outlook;
- independent replication is incomplete.

The breadth comes from the **research question and mechanism**, not from pretending that the validation surface is universal.

## 5. Why the engineering layer matters scientifically

The repair work is not included merely as a product feature.

It tests whether the proposed semantic object is operationally addressable.

If a disputed Process Reality lineage can be:

- located;
- content-addressed;
- bounded by an affected closure;
- selectively reopened/recomputed;
- repaired while preserving unrelated state;
- watched for re-entry;

then the theory has an intervention/control surface.

This turns Process Reality from a retrospective label into a candidate reliability object.

## 6. Why the first paper can remain small in scale

The first paper should not compete on API budget or model count.

Its strategy is mechanism-first:

> **small enough to reconstruct completely, broad enough to expose a general reliability question.**

The role of the initial paper is to establish:

- phenomenon;
- distinction from ordinary propagation/persistence;
- measurement object;
- intervention surface;
- repair surface;
- bounded future generalization programme.

Large cross-model/provider replication can then test robustness without redefining the object.

## 7. Editorial-risk ledger

The paper still carries real desk-review risks:

| Risk | Current status |
| --- | --- |
| Single subject-model family | explicit external-validity limitation |
| Retrospective semantic rubric | explicit retrospective-mechanism framing |
| Semantic reviewer dependence | independent blinded replication incomplete |

| Inter-system breadth | outlook only |
| Provisional references | P5 task |
| Figures not yet rendered | P5 task |
| R8 repository gzip defect | P6 blocker with verified recovery source |

None should be hidden.

They should define the exact level of claim.

## 8. Manuscript narrative for broad readership

The manuscript should preserve the simple conceptual order:

1. **The value stayed the same; its permission to count as reality changed.**
2. Define Process Reality.
3. Show C/P/R as dynamic permission dimensions.
4. Show functional semantic lineage.
5. Challenge authority locally.
6. Distinguish normal inheritance from stronger inertia.
7. Repair an addressable lineage instead of rerolling the whole system.
8. End with process qualification and bounded future system-level questions.

This avoids leading with R-stage nomenclature or repository engineering.

## 9. P4 final editorial position

The paper should not claim:

> “This is important because it applies universally.”

It should claim:

> **The study exposes a process-level reliability variable that endpoint evaluation can miss, gives it a traceable mechanism, and shows that the affected semantic process can become an addressable repair object.**

That is the strongest current significance statement supported by the first-paper evidence.
