# Process Reality Cross-Domain First-Round Experiment Plan v0.1

Date: 2026-09-18  
Status: **FROZEN PROTOCOL CANDIDATE / OFFLINE-READY TARGET / REAL PROVIDER NOT AUTHORIZED**

## 1. Purpose

The first-round experiment is no longer defined as replaying the historical ecommerce method-development sequence in every domain.

The ecommerce domain is the method-development/reference case. Finance, supply-chain and software-engineering are frozen-protocol replication domains.

The replication principle is:

> **Replicate the frozen method, not the history of method development.**

The first-round experiment therefore tests whether the same Process Reality observation and control framework can operate across four different domain semantics while keeping the Arena/runtime protocol fixed.

## 2. Domain cohort

| Domain | Arena role | Cohort role |
|---|---|---|
| ecommerce | E-commerce Operations | method-development reference + fresh final-protocol replication |
| finance | Corporate Credit Decision | frozen-protocol replication |
| supply_chain | Supply-chain Allocation | frozen-protocol replication |
| software_engineering | Production Release Decision | frozen-protocol replication |

All four domains are already registered in `arena/config/arena_v0.3.json`.

## 3. Sample plan

The existing Arena default is retained for the first-round target:

- 30 natural trajectories per domain;
- 4 domains;
- 120 planned natural trajectories total.

Execution is operationally split into six fixed waves:

- 5 trajectories per domain per wave;
- 20 trajectories per wave;
- 6 waves total.

All 120 rows are preregistered in one manifest before real subject execution. Waves are execution partitions only. They are not outcome-aware sample expansion.

A wave may be paused for technical/budget reasons, but the planned sample must not be changed because a domain looks favorable or unfavorable.

## 4. Protocol lock

The first real cross-domain provider call freezes the following for the whole first-round natural cohort:

- Arena runtime/config;
- Agent prompt protocol;
- model/provider config;
- four domain fixture files;
- recording schema;
- structural derivation/index version;
- theory/measurement/scout bindings;
- first-round plan hash;
- execution code SHA.

All waves must use the same execution code SHA.

The three replication domains must not receive domain-specific method changes after outcomes are observed.

Historical ecommerce experiments remain frozen and separate from the new first-round natural cohort.

## 5. Unified execution path

```text
S1 Natural Collection
  -> S2 Raw Freeze + Structural Derivation
  -> S3 Localized Semantic Audit / Case Qualification
  -> [if qualified] S4 R5 Atomic Probe
  -> [if R5 run] S5 R6 Full Descendant / Inertia Observation
  -> [if completeness gate passes] S6 R7 Semantic-Lineage Scoped Repair
  -> [if R7 run] S7 Post-Repair Watch
```

R2/R3/R4 are simultaneous views over the same natural trajectory, not separate subject runs.

R5, R6 and R7 are conditional extensions of a frozen natural case. They are not compulsory for every domain.

## 6. S1 — Natural collection interface

S1 records natural multi-Agent trajectories only.

Required outputs per run include:

- actual model inputs;
- raw model outputs;
- parsed actions;
- message send/read lifecycle;
- invocation send/read/execution lifecycle;
- shared-state before/after;
- shared-state metadata;
- model-call event ranges;
- queue/termination state;
- snapshots and journal hash chain;
- usage/cost where available.

No probe, active repair or paid semantic evaluator is allowed in S1.

## 7. S2 — Freeze and structural derivation

Raw evidence must be frozen before structural derivation.

Deterministic derivation may produce:

- content-address index;
- Structural Repair Anchor candidates;
- pool visibility ledger;
- source/writer/event provenance;
- downstream structural-closure candidates;
- candidate semantic-audit windows;
- optional support/pool/exposure candidates.

Mechanical visibility does not establish semantic adoption.

## 8. S3 — Localized semantic audit and case gate

Structural candidates do not automatically become R5 targets.

A case can advance only after an append-only, evidence-bound localized semantic audit records:

- exact source proposition/status;
- transformation/adoption relation;
- candidate shared-state authority;
- downstream use/decision dependence;
- competing interpretation;
- candidate target identity and content address;
- audit status.

Possible case statuses include:

- `NO_QUALIFYING_NATURAL_STRUCTURE`;
- `AWAITING_LOCALIZED_SEMANTIC_AUDIT`;
- `ELIGIBLE_R5_ATOMIC_PROBE`;
- `NOT_ELIGIBLE_R5`.

A no-qualifying-structure result is a valid first-round result. It must not trigger target invention or domain-specific redesign.

## 9. S4 — R5 atomic probe

For an eligible natural target:

- exactly one direct authority withdrawal;
- zero reinjection;
- no experiment-origin persistent shared-state mutation;
- then immediate return to natural continuation.

The target must be selected before probe outcome is observed.

The historical ecommerce operator-development sequence is not replayed.

## 10. S5 — R6 full descendant / inertia observation

R6 observes the complete relevant post-probe continuation and separates:

- direct/local response;
- carrier visibility;
- semantic adoption;
- relation propagation;
- post-consumption System Inertia;
- natural/random process variation;
- target specificity when evidence permits.

A large topology change alone is not System Inertia.

## 11. S6 — R7 final repair path

R7 is allowed only if the Semantic Lineage Completeness Gate passes.

The replication domains use the final operator directly:

`Semantic Lineage Package -> affected closure -> compatibility partition -> invalidation/reopen -> selective recompute -> new lineage -> post-repair watch`

Forbidden replication behavior:

- historical stochastic target replay;
- deliberately repeating obsolete C3 operators merely to reproduce ecommerce development history;
- whole-system reset presented as localized repair;
- semantic CPR adjudication inside R7.

`LINEAGE_GAP` blocks active repair.

## 12. S7 — Post-repair watch

Where R7 runs, monitor:

- exact old-lineage re-entry;
- authority escalation;
- target semantic rewrites;
- structurally equivalent recurrence candidates;
- closure expansion;
- compatible-state preservation;
- stability within the observed horizon.

The watch does not prove permanent absence outside its horizon.

## 13. Cross-domain comparison

The first-round cross-domain comparison has four levels:

1. **Occurrence** — does a qualifying Process Reality structure naturally appear?
2. **Mechanism** — if it appears, what source -> transformation -> pool/adoption -> inertia path is observed?
3. **Trajectory** — which Agent structural path carries that mechanism?
4. **Repairability** — if a problematic lineage is sufficiently complete, can it be repaired while compatible state is preserved?

The comparison must not force all domains into the same semantic object or Agent path.

## 14. Independence and generalization boundary

The four domains differ semantically but share the same Arena architecture, model/provider and minimal Agent protocol.

Therefore the first round can support cross-domain replication **within one frozen Free-Agent Arena architecture**.

It does not by itself establish cross-architecture or cross-model generality.
