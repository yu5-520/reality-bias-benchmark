Date: 2026-10-06

This packet integrates the two sealed enhanced-repair contrasts into the existing

## 1. Publication role

The new experiments belong in the existing **bounded repair / engineering
extension** part of the paper. They do not create a new benchmark claim and they
do not replace the Stage-II population analysis.

The publication sequence should be:

`old local repair -> enhanced route repair -> live obligation repair -> descendant regeneration`

The scientific point is not that the enhanced repair system universally closes
trajectories. The point is that the new contrasts separate three quantities that
the earlier manuscript could only state conceptually:

1. direct target change;
2. intervention locality / mutation breadth;
3. downstream process repair.

The frozen result is that these quantities can move independently.

## 2. Results passage — replace or extend the old bounded-repair ending

The historical local repair already showed that a one-shot intervention could
change a target without reliably repairing the subsequent process. We therefore
used the enhanced monitor and complete route reconstruction as a fixed input to
two additional same-path mechanism contrasts. These contrasts were not retries
of the original repair arm and were not used to estimate a new success rate.

In G3-X4-T2, the canonical local process revision and the enhanced route repair
started from the same sequence-4 parent, with the same task, model profile,
60-turn remaining horizon and 64-turn native ceiling. The local arm had
previously been classified as regeneration: its continuation used five subject
writes across three references, entered backend/security/delegation work and
reached the turn ceiling. The enhanced treatment used a prefix-only,
source-bound route plan and one native MCP correction to the alternate launcher,
then returned the unchanged subject system to all 60 remaining calls. The route
correction persisted. Relative to the local arm, subject writes fell from 5 to
2, backend turns from 13 to 5, security participation from 3 turns to none, and
delegation from 4 actions to none. The additional `checkout_app/api.py` path
did not reappear. However, the trajectory still reached turn 64. Work shifted
from broad implementation expansion toward repeated frontend/QA/review
activity rather than closing.

To test whether the remaining persistence was carried by live collaboration
obligations, we then froze a nested contrast at history 24 of the enhanced
trajectory. At that point the application-route correction and payment-button
implementation were already present, while four pending messages still asked
agents to implement, reshape or further test the same feature. The treatment
replaced only those four pending message contents, preserving their senders and
leaving the queue, history, task and application files unchanged. The immediate
behavior changed: the corresponding frontend continuation reported that the
request was already satisfied and made no changes. Yet the branch again used
all 40 remaining turns. Later agents generated new messages asking how to add
the payment button and how its placement, label, loading and error behavior
should work. These were not literal copies of the repaired messages. The
operational obligation was reconstructed through descendants.

Together, the contrasts show that repair locality can improve before process
closure improves. A target can be source-bound, repaired and behaviorally
effective at the local node while the larger task/collaboration route remains
capable of regenerating equivalent authority through other carriers.

## 3. Mechanism wording for Discussion

These observations refine the engineering implication of process reality.
A complete node graph is useful not because every connected node should be
edited, but because a local repair must be evaluated against the remaining
authority route. In the first enhanced contrast, route-aware repair narrowed the
mutation surface but left inherited collaboration obligations active. In the
second, those obligations were locally superseded and immediate behavior changed,
but equivalent task pressure later re-entered through newly generated descendant
messages. This separates carrier repair from route repair and explains why
successful local mutation is not sufficient evidence of restored process
reality.

The conservative engineering principle is therefore:

> repair the smallest evidence-supported set of authority carriers that can
> prevent regeneration, exit the intervention, and observe the untouched
> remainder.

This is a mechanism observation, not a universal repair-success claim.

## 4. Methods insertion

The enhanced-repair contrasts used frozen G3-X4-T2 evidence and introduced no
Natural-A rerun. For the first contrast, the control was the existing canonical
local repair (workflow `36309205795`). The enhanced arm started from the same
sequence-4 checkpoint
`98a72990529ea23b994511beb7bdf19ac5f3aa29c5e06a748711c3362455a2f3`,
used a prefix-only source-bound route specification with zero planning-model
calls, executed one native MCP application repair, and released the original
subject system for the complete 60-turn remaining horizon. No automatic retry
or paid semantic reviewer was used.

The coordination-obligation follow-up was a separately frozen nested contrast
from history 24 of that enhanced trajectory. The frozen control suffix was not
rerun. The treatment replaced four pending message contents while preserving
their original senders and leaving queue order, prior history, task, application
files and native ceiling unchanged. One provider-bearing treatment was executed
for the remaining 40 turns. A preceding workflow failure occurred before
provider dispatch and is not counted as a scientific attempt.
